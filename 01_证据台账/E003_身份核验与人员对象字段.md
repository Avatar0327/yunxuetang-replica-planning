**【已验证】关键数据模型事实**：人员与组织是 **1 主部门 + N 兼职部门** 的关系，不是简单的一对一。
→ **规划含义**：学习任务的「按部门指派」与报表的「按部门统计」必须明确：兼职部门是否纳入范围？同一人在主部门与兼职部门是否重复计数？此为**待用户决策项 DIFF-02**，且需在原站验证原站口径（V-05）。

**【已验证】** 个人资料页所有字段均为 `disabled` 只读，含手机/邮箱以外字段个人无法自助修改 → 人员档案由管理侧/上游系统维护。

## 4. 空值展示约定【已验证】——第二处证据
本页用 **`暂无`** 表示空值（工号、入职日期、兼职部门）。
结合 E002 的 `--` 与 `0`，原站目前**至少存在三种空值表示**：

| 表示 | 出现位置 | 语义 |
|---|---|---|
| `暂无` | 个人资料等表单/详情页 | 字段未填写 |
| `--` | 数据看板计数类指标 | 无数据/不适用 |
| `0` / `0%` | 数据看板部分计数类与比率类 | 有统计，值为零 |

**【已验证】原站空值表示不统一。**
**规划建议**：目标产品建立统一的空值语义规范，明确区分「未配置」「无数据」「值为 0」三态并固定各自展示符号。列入 **DIFF-03（建议有意差异）**。

## 5. 手机绑定状态的重要发现【已验证】
admin 完成登录环节的手机号验证后，**个人资料中「手机」仍为未绑定状态**（占位文案「请绑定手机号」）。

→ 【已验证】登录时的手机验证与**个人档案的手机绑定是两套独立机制**，登录验证不会回写档案。
→ 【受限验证】该登录验证更可能是**一次性安全校验/风控挑战**，而非账号绑定。
→ **规划含义**：若目标产品要做登录二次验证，须明确验证用的联系方式来源（档案字段 or 独立的安全设置），不可假设二者同源。列入需求基线待办。
