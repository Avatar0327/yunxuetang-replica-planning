## 1. ⭐⭐⭐ 「浏览 / 学习 / 完成」三态的官方定义【已验证】
> **这是本次调研对规划要求「区分打开页面、播放内容、记录进度、课程完成」的决定性答案。**

课程统计报表提供**三个层级、互相独立**的指标，每个都有原站官方定义：

| 层级 | 指标 | 官方定义原文 |
|---|---|---|
| **① 浏览** | 浏览人数 | 「所选时间段内，**浏览**该课程的总人数」 |
| | 浏览次数 | 「所选时间段内，该课程**被浏览的总次数**」 |
| **② 学习** | 学习人数 | 「所选时间段内，**学习**该课程的总人数」 |
| | 学习人数（在线课堂） | 「所选时间段内，**从在线课堂自主学习**该课程的总人数」 |
| **③ 完成** | 完成人数 | 「所选学习时间内，**完成**该课程学习的人数」 |

**【已验证】结论**：
- **浏览 ≠ 学习 ≠ 完成**，是三个独立统计的行为层级
- 浏览同时有**人数**与**次数**两种口径；学习与完成只有人数
- 「学习人数（在线课堂）」单独拆出 → 再次印证 E007 §3 的**入口来源区分**

## 2. ⭐⭐⭐ 「打开即完成」的特殊规则【已验证】——最反直觉的一条

课程统计报表页顶部的注意事项原文：

> **注意，若学员已完成某课程，则当其参与的新项目包含相同课程且开启进度同步时，学员打开课程即完成，系统自动将其计入该课程的完成人数；若学员没有继续学习的行为发生，将不会计入学习人数。**

### 规则解析【已验证】
前置条件：
1. 学员**此前已完成**课程 X
2. 学员加入**新项目**，该项目包含课程 X
3. 该项目**开启了「同步在线课堂中的课程学习进度」**（E009 §2.4 的开关）

结果：
- 学员**只要打开课程 X 即判定为完成** → **计入完成人数**
- 若学员**没有继续学习行为** → **不计入学习人数**

### 【已验证】这意味着
**同一个人在同一统计周期内，可以「被计入完成人数」但「不被计入学习人数」。**
即：**完成人数 与 学习人数 的差值是有业务含义的**，不是数据错误。

### 规划含义（必须写入需求基线与验收场景）
1. 「完成」不等于「本期发生了学习」。目标产品的完成判定必须区分：
   - **本期新完成**（有学习行为）
   - **继承性完成**（历史已完成 + 进度同步带来的自动完成）
2. **验收场景必备**：「学员曾完成课程A → 加入含课程A且开启进度同步的新项目 → 仅打开不学习 → 预期：完成人数+1，学习人数不变」。
   若不写入验收，此行为一定会被测试人员当成 Bug。
3. 这条规则**依赖项目级的「进度同步」开关**（E009 §2.4）。若 V1 不做双入口（DIFF-12），则此规则不适用——**但也就失去了"学员不必重复学已学过的课"这一体验优势**，属于必须向用户说明的取舍。列入 **DIFF-17**。
4. 【未验证】若进度同步关闭，同一课程在新项目中是否需要**从头重学** → **V-40（高优先）**

## 3. ⭐ 学习时长的补充规则【已验证】
> **学习时长（min）：所选学习时间内，该课程被学习的时长，人员学完该课程后的继续学习也算进该课程被学习的时长**

**【已验证】** 完成后的继续学习**仍然累计学习时长**。
→ 学习时长是**行为累计量**，不因完成而封顶。
→ 结合 E008 §3.4（倍速播放可倍速计时长），「学习时长」口径需同时声明：倍速规则 + 完成后继续累计规则。

## 4. ⭐ 活跃时长的官方定义【已验证】
平台活跃统计报表说明原文：
> **登录学员端并保持在线状态即可累计活跃时长，最小统计单位为 1 分钟（不足 1 分钟按 1 分钟计算）**

**【已验证】关键口径**：
- 活跃 = **登录学员端 + 保持在线**（不要求任何学习行为）
- **最小单位 1 分钟，不足 1 分钟向上取整**
- → 这是「打开页面」层级的度量，与「学习」完全分离，印证 E002 §4.2

**规划含义**：向上取整会**系统性高估**活跃时长（每次短会话至少计 1 分钟）。目标产品若要保留，需在指标说明中写明；若改为真实累计，属有意差异。列入 **DIFF-18**。

## 5. ⭐ 对 E007 §2 的重要修正【已验证】

E007 曾记录「仅统计启用人员，不统计禁用、删除人员和游客的数据」。
**本次发现：该规则仅适用于「数据大屏 / 平台总览」，不适用于报表中心。**

报表中心的「**学员状态 / 人员状态**」是**可选筛选项**，选项为：
> **启用 / 禁用 / 删除**（默认选中「启用」）

**【已验证】修正后的结论**：

| 数据域 | 人员状态处理 |
|---|---|
| 数据大屏 / 平台总览 | **硬性排除**禁用、删除人员与游客 |
| 报表中心明细报表 | **可筛选**，默认「启用」，但**可查询禁用与已删除人员的数据** |

→ 这大幅缓解了 E007 §2 提出的「历史报表不可复现」风险：**明细数据仍可追溯**，只是看板不含。
→ **DIFF-06 的处置建议相应调整**：目标产品可沿用「看板默认只看在职、明细可查全量」的分层设计，这其实是合理的产品决策，**不应简单判为缺陷**。
> ⚠️ 本条是对先前判断的修正，已在此显式标注，避免两处口径冲突。

## 6. ⭐ 组织范围与兼职人员的口径【已验证】——V-05 的答案

平台活跃统计的查询字段「部门人数」带官方说明：
> **部门人数：当前部门下的人数，不包含兼职人员**

**【已验证】** 按部门统计时，**兼职部门的人员不计入该部门人数**，只按主部门归属。
→ 回答 V-05：**兼职部门不纳入部门统计范围**。

另有独立开关：**`统计子部门数据`：是 / 否**
**【已验证】** 组织范围是否向下聚合**由使用者选择**，不是固定规则。

**规划含义**：目标产品的部门统计必须明确三件事，缺一不可：
1. 按主部门还是含兼职部门（原站：**仅主部门**）
2. 是否含子部门（原站：**可选**）
3. 人员状态过滤（原站：**可选，默认启用**）

## 8. ⭐ 课程对象的补充字段【已验证】——E008 的重要补全

课程统计的「课程信息」可选字段，暴露了课程对象的**完整属性集**（较创建表单多出 10 项）：

| 字段 | E008 创建表单中是否可见 | 说明 |

| 贡献者 / 作者 / 主讲老师 / 辅讲老师（及各自部门） | ✅ | 报表额外提供「部门」维度 |
| **课程状态** | 部分（列表见「未发布」） | 状态机字段 |
| **课程类型** | ❌ **新增** | 与「课程来源」并列 |
| **课程目录** | 隐含（catalogId） | |
| **课程来源** | 隐含（首页有内部/外部切换） | 内部 / 外部 |
| **是否隐藏** | ✅ | |
| ⭐ **是否过期** | ❌ **新增** | **课程本身有有效期/过期概念** |
| ⭐ **标准时长(min)** | ❌ **新增** | 课程级标准时长（推测由任务时长聚合） |
| ⭐ **标准学分** | ❌ **新增** | 课程级标准学分 |
| **课程评分** | ❌ **新增** | 学员评分聚合 |
| ⭐ **推荐系数** | ❌ **新增** | 推荐算法权重 |
| **上传时间 / 更新时间** | ❌ **新增** | |
| **上传者 / 上传者账号 / 上传者部门** | ❌ **新增** | **与「贡献者」是不同字段** |
| ⭐ **审核人** | ❌ **新增** | **课程存在审核流程**（呼应 E004 的「审核中心」） |

**【已验证】三条重要补充**：
1. **课程有「是否过期」属性** → 课程本身可设有效期，与项目有效期、任务时间并列，构成**第四层时间**。
   → 更新 E012 §4 的时间层级结论：共 **4 层时间**（课程有效期 / 项目时间 / 学员周期 / 任务起止）。**V-38 的冲突分析范围相应扩大。**
2. **课程有「审核人」** → 课程发布前存在审核环节。V1 是否引入审核流需用户决策 → **DIFF-19**。
3. **「上传者」与「贡献者」是两个不同字段** → 课程的人员关系比创建表单显示的更复杂（上传者/贡献者/作者/主讲/辅讲/审核人，共 6 类）。

## 9. 报表中心完整目录【已验证】（33 个入口）
按 URL 前缀归域：

| 域前缀 | 报表 |
|---|---|

**【已验证】报表的通用交互模式**（可直接复刻）：
`报表说明文案` + `可保存的筛选器（默认筛选器/保存为筛选器）` + `筛选条件区` + `可勾选的查询字段区（全选/取消全选）` + `查询` + `导出` + `重置筛选`
- **字段可选**：用户自选输出列，而非固定表格 → 好设计
- **筛选器可保存复用** → 好设计
- **导出为异步任务**（呼应 E004 的「下载中心」）
