## A 类：原站缺陷，明确不复刻（**8 项**）

### DIFF-27【A】🆕「课程」一词指代三种不同对象 —— 口径混用
- **原站行为**（E018 §5，网页实测验算吻合）：
  | 位置 | 数值 | 实际统计对象 |
  |---|---|---|
  | 首页看板「**课程总量**」 | 129 | **课件** |
  | 分类管理「**课程数**」 | 132 | **课件 + 课程包** |
  | 课程管理列表 | 3 | **课程包** |
  - 验算：129 课件 + 3 课程包 = 132 ✓
- **问题**：同一个"课程"在三处指代三种对象，管理员无法判断看板数字的含义。
- **建议**：目标产品严格区分 **课件（Courseware，单个内容）** 与 **课程（Course，内容包）**，所有指标显式标注统计对象。
- **附带修正**：这也推翻了我此前"admin 课程可管理范围受限"的推测（V-50 作废）——admin 能看到全部 129 个课件。

### DIFF-28【A/C】✅ **已决策（D-23）** 课程下架后无法学习
- **原站行为**【手册记载】（在线课堂手册·课件维护）：「**下架：下架后知识/课程将无法学习，重新上架后恢复**」
- **冲突说明**：我在 v1.0 的 REQ-CRS-05 中规定"下架后已在学学员可继续完成"，理由是避免业务事故。**这与原站不一致。**
- **网页未实测**（V-25 未结案）。
- **两个选项**：
  - ① **复刻原站**：下架即所有人无法学习（简单、与手册一致）
  - ② **保留我的设计**：下架后已在学学员可完成，但禁止新指派
  - **我的建议**：**采用①复刻原站，但下架前强制提示"当前有 N 名学员在学，下架后他们将无法继续"**，把风险交给操作者判断。
- ✅ **用户已决策 D-23：采用①复刻原站 + 下架前强制提示在学人数。**

### DIFF-10【A】课程创建路由缺陷 —— 会产生重复对象
- **原站行为**（E008 §8，本次亲历复现）：`/kng/#/operator/course` 路由**永远是"创建"语义**，但会**预填上一次未完成的草稿数据**，页面标题仍显示「创建课程」；「下一步」按钮**隐式承担提交创建**，无二次确认、无防重复提交保护。
- **实际后果**：调研中因此**意外产生了 2 门重复草稿课程**。
- **建议**：目标产品必须 ① 创建与编辑路由分离，编辑路由以资源 ID 为准并显示「编辑」标题；② 分步表单显式区分「保存草稿」与「下一步」；③ 加幂等键或提交锁。
- **验收要求**：「连续两次进入创建流程不应产生重复对象」必须进重复操作验收场景。

### DIFF-29【A】🆕 取数接口失败时，看板降级显示 `0` —— 最严重的一条
- **原站行为**（E018 附录，2026-09-21 平台故障期间实测）：服务端返回 502 时，首页看板**所有指标归零**（启用人数 156→0、课程总量 129→0），**没有任何错误提示**。约 20 分钟后部分恢复（启用人数回到 156，课程总量仍为 0）。
- **问题**：管理员**无法区分"真实值为 0"与"取数失败"**——两者显示完全相同。可能据此做出错误的运营决策（如误判"本月无人学习"而发起大规模催办）。
- **与 DIFF-01/03 的关系**：同一个系统性问题——**原站缺乏统一的"无数据/零值/异常"语义**。
- **建议**：目标产品必须区分**四态**且视觉可辨：
  | 状态 | 展示 |
  |---|---|
  | 正常有值 | 数值 |
  | 真实零值 | `0` |
  | 无数据/不适用/分母为0 | `--` |
  | **取数失败** | **明确错误态 + 重试入口，绝不降级为 `0`** |
- **验收**：AC-E-14🆕 模拟统计接口 5xx → 看板显示错误提示与重试，**不显示任何数字**。

### DIFF-32【A】🆕 学员端与报表端的学习时长口径不一致
- **原站行为**【E017 V-48 结案实证】：同一条学习记录——
  - 学员端「我的学习」：**学习 0 分钟**
  - 报表端「个人学习详情」：**有效学习时长 1.92 min / 累计学习时长 3.82 min**
- **问题**：学员看到"学了 0 分钟"会以为学习没被记录，可能重复学习或投诉。**而数据其实是对的。**
- **建议**：学员端与报表端取同一字段同一口径；学员端展示时长时明确是「有效学习时长」。
- **验收**：AC-E-21。

### DIFF-01【A】比率指标在分母为 0 时显示 `0%` 而非 `--`
- **原站行为**（E002 §5）：项目/考试全无数据时，计数类显示 `--`，但学习率、完成率、通过率显示 **`0%`**。
- **问题**：无人参考时「通过率 0%」会被误读为"全员没通过"，实际是"没人考"。
- **建议**：目标产品统一为**分母为 0 时比率显示 `--`**。

### DIFF-03【A】空值表示不统一（三种并存）
- **原站行为**（E002 §5 / E003 §4）：`暂无`（表单详情）、`--`（看板计数）、`0`/`0%`（部分看板）三种表示混用。
- **建议**：建立统一空值语义规范，明确区分**「未配置」「无数据」「值为 0」**三态并固定展示符号。
- **备注**：这直接对应你提出的「业务数据定义应区分稳定身份、版本、未配置、空值和0」。

### DIFF-08【A】同一概念在不同页面使用不同计数单位
- **原站行为**（E008 §1 / E002 §4.3）：课程管理列表用「**学习人数**」，首页看板用「**学习人次**」。
- **建议**：目标产品每个指标**显式标注单位（人数/人次）**并全站统一，不允许同名不同义。
