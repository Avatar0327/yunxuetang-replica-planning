# 一、管理员旅程：从「有培训需求」到「看到结果」

## 主流程
```
① 建内容        ② 定范围        ③ 发任务        ④ 盯进度        ⑤ 出结果
分类→课程→任务 → 项目→指派规则 → 发布项目 → 督学/催办 → 报表/导出
```

## 分步展开

### ① 建内容
| 步骤 | 系统行为 | 状态变化 | 依赖 |
|---|---|---|---|
| 建分类 | 配置分类权限矩阵（主体×浏览/维护/分发），可设为公开、可继承 | — | 组织（指定用户时） |
| 建课程 | 填名称、分类（均必填），选可见范围（跟随分类/单独设置） | 草稿 | 分类 |
| 加任务 | 添加文档/视频任务，逐个设**是否必修**、**是否计入完成度**、时长、学分 | 草稿 | 课件 |
| 发布 | 正式对学员可见 | 草稿 → **已发布** | — |

**关键规则**：
- 【原站已验证】**编辑与生效分离**。原站原文：「本次编辑未正式发布对学员可见，仅存储在当前页面…如需正式发布对学员可见，请先正式保存发布。」
- 【原站已验证】课程标准学分 = 任务时长之和 × 0.1。

**异常路径**：
- 名称或分类为空 → 提交被拒，错误指向具体字段。
- 🔴 重复进入创建流程 → **不得产生重复课程**（原站在此有缺陷，DIFF-10）。

### ② 定范围
| 方式 | 维度 | 触发 |
|---|---|---|
| 手动添加 | 逐人选择 | 即时 |
| **规则自动加入** | **部门 / 岗位 / 用户组 / 入职时间**，可选 **OR / AND** | **每天定时扫描** |
| 动态用户组联动 | 组成员变动自动同步 | 近实时（V1 不做） |
| 主管添加 | 本团队成员 | 取决于项目开关 |

**【原站已验证-否定结论】标签不是指派维度。** 若业务需要按标签指派，属**新增需求**。

### ③ 发任务
| 步骤 | 状态变化 |
|---|---|
| 配置项目模式 | 起止时间模式（统一日期） / **周期模式**（每人独立起算） |
| 设完成标准 | 「完成全部必修任务」（V1 固化） |
| 发布项目 | 未发布 → **进行中** |

**跨模块依赖**：项目 → 课程（任务引用）→ 分类权限（可见性）→ 组织与人员（指派范围）。

### ④ 盯进度
- 学员列表可按**完成状态**、**逾期状态**、必修进度筛选 → 精准定位"该催谁"。
- 【原站已验证】原站支持自动督学：项目结束前 / **阶段逾期前** / 任务结束前 / 固定时间，并可**把学习进度自动发送给学员的直属经理**。V1 仅做人工筛选，自动督学进 V2。

### ⑤ 出结果
- 三张报表：课程学习详情 / 个人学习详情 / 部门学习汇总。
- **每张报表必须标注刷新节奏**。

**异常路径**：
- ⚠️ 刚有学员完成 → 汇总看板当日可能无数据（T-1 口径），**不是故障**。
- ⚠️ 浏览人数 ≠ 学习人数 ≠ 完成人数，且三者不必然递减（因"打开即完成"规则），**不是数据错误**。

# 二、学员旅程：从「收到任务」到「完成」

## 主流程
```
① 看到任务      ② 打开课程      ③ 开始学习      ④ 完成          ⑤ 获得反馈
我的学习列表 →  课程详情页   →  点击开始学习 →  满时长判定  →  学分/标签/评价
```

## ⭐ 五态分离（本次调研的核心成果）

| 态 | 学员的动作 | 系统记录 | 统计指标 | 界面证据 |
|---|---|---|---|---|
| ① **未开始** | 任务出现在列表 | 完成状态=未开始 | 覆盖人次 | 我的学习列表 |
| ② **打开页面** | 进入课程详情 | — | **浏览人数/浏览次数** | 页面显示"已完成 0%"，**视频不自动播放** |
| ③ **播放内容** | 点击「开始学习」 | 实际开始学习时间 | **学习人数** | 必须显式点击 |
| ④ **记录进度** | 持续观看 | 进度%（**约20秒节流上报**） | — | 66s显示52%，97s显示70%（滞后） |
| ⑤ **课程完成** | 累计观看满总时长 | 完成状态=已完成 | **完成人数** | 状态变"已完成学习"+弹评价窗 |
| ⑥ **项目完成** | 全部必修任务完成 | 项目完成状态 | 项目完成人次 | 项目头部常驻完成标准 |

**【原站已验证】② 与 ③ 之间必须有一次显式点击**，这是"打开页面 ≠ 学习"的界面级保障。

## 完成的连锁反应【原站已验证，实测】
```
课程完成
 ├─ 学分 +（时长×0.1）        V1 做
 ├─ 标签授予（写入人员属性）   V1 做
 ├─ 完课评价弹窗             V1 做
 ├─ 积分 / 勋章 / 经验值      V1 预留
 └─ 项目完成度重算 → 可能触发项目完成
```

## 异常路径
| 场景 | 预期 |
|---|---|
| 学习中途关页面 🔴 | 进度不丢失（要求卸载补报） |
| 项目已截止仍想学 | 被拒，提示项目已结束 |
| 逾期但未完成 | 完成状态"学习中" + 逾期状态"已逾期"，**两者并存** |
| ⚠️ 已学过的课出现在新项目 | 打开即完成；完成人次+1，学习人次不变 |
| 课程被下架 🔴 | 已在学可继续完成 |
| 无权限访问某课程 | 页面内友好提示 + 补救路径，不用 403 |

# 三、主管旅程：从「关心团队」到「推动完成」

```
① 看到团队    ② 定位问题      ③ 推动        ④ 复核
我的团队  →  筛选未完成/逾期 → 提醒/加人 → 团队报表
```

## 关键规则
- 【原站已验证】主管的数据范围来自**人员档案的「直属经理」字段**，不从组织树推导。原站实测：项目学习进度**自动发送给学员的直属经理**。
- 【原站已验证】主管能否在项目中增删学员，**由项目设置开关「允许团队管理者添加移除学员」决定**，不由角色决定。
- 🔴 主管范围是仅一级下属还是多级，**原站未验证**。V1 规定为**多级递归**。

## 异常路径 🔴
| 场景 | 预期 |
|---|---|
| 查看非下属数据 | 结果为空 + "超出你的数据范围" |
| 看团队成员手机号 | **脱敏**显示 `138****1234` |
| 项目关闭了主管加人开关 | 按钮不可见，直接调接口被拒 |

# 四、状态机汇总

## 课程
```
草稿(未发布) --发布--> 已发布 --下架--> 已下架
                         ↑__重新发布__|
```
🔴 下架后行为为设计决定：已在学可完成，禁止新指派，不出现在自主浏览。

## 项目【原站已验证，部分】
```
未发布 --发布--> 进行中 --(截止+自动结束)--> 已结束 --(自动归档)--> 已归档
                                              ↑
                            「延期学习学员」可继续学习（例外路径，V1 不实现）
```
【未验证】手动结束 / 暂停 / 作废（V-30）。

## 学习记录（双状态正交）
```
完成状态：  未开始 → 学习中 → 已完成
逾期状态：  未逾期 → 已逾期
```
**两者独立，可组合为 6 种状态**。其中「学习中 + 已逾期」是管理员最需要关注的组合。

## 人员
```
启用 ⇄ 禁用 → 删除(软删) --恢复账号--> 启用
```
【原站已验证】删除为软删除，存在"恢复账号"功能。

# 四b、其他模块的业务流程

> ⚠️ **D-35 后范围变更**：下述 **考试闭环（4b.1）** 与 **调查闭环（4b.3）** 已进需求池，**本期不实施**；

## 4b.1 考试闭环 📋 需求池
```
① 建题库      ② 组卷        ③ 排考         ④ 作答        ⑤ 批阅        ⑥ 出成绩
题库→题目  →  试卷(固定/随机) → 考试安排  →  学员作答  →  批阅人批阅  →  成绩与统计
```

| 环节 | 关键规则 | 证据 |
|---|---|---|
| 组卷 | **固定出卷 / 随机出卷**；与循环考试交互（固定→每次相同，随机→每次随机） | E014 §1 |
| 排考 | 三步向导：创建试卷→编辑试题→发布考试 | E014 §2 |
| 分数线 | **及格线 + 优秀线双线**，各支持固定分数/总分比例；**默认及格 = 总分 60%** | E014 §3 |
| 次数 | `不限次 / 限制次数(默认2)` + `考试通过后不允许再次考试` | E014 §12 |
| 批阅 | 批阅人可为 `创建人/部门经理/直属经理/指定/定向`；支持**匿名批阅**与 **AI 智能批阅** | E014 §6/§7 |
| 成绩 | **首考与补考分列存储**，非覆盖式 | E014 §5 |
| 与项目联动 | `考试通过移除任务卡片`（D 决策：以通过为准）；**项目发布后不可改** | E014 §8、E018 §6.6 |

**异常路径**：
- 学员交卷但未通过 → 任务仍未完成，项目完成度不增加
- 开启「通过后不允许再次考试」→ 已通过学员无法重考
- ⚠️ 多次作答的成绩取值：**原站无配置项**，目标产品须显式定义（DIFF-30）

## 4b.2 面授闭环 ✅ **本期实施（D-38 前移）**
```
① 建面授        ② 配场次与考勤      ③ 加学员        ④ 现场签到      ⑤ 录成绩      ⑥ 判完成
基本信息+时长  →  场次(≤15)+考勤规则 → 指派/扫码加入 → 签到签退(围栏) → 考核成绩录入 → 完成标准判定
```

| 环节 | 关键规则 | 证据 |
|---|---|---|
| 时长 | **发布后不可修改**；推送模式 `即学即推 / 核实下发` | E021 §3 |
| 场次 | **最多 15 个**，各自独立时间/地点/考勤要求 | E021 §4 |
| 考勤 | 签到/签退时间范围各两个参数；**扫码 + 电子围栏** | E021 §5 |
| 请假 | **一等状态，需审批**（D-24：单级固定审批） | E021 §5 |
| 完成 | **组合逻辑 × {完成场次考勤, 录入面授考核成绩}**，至少选 1 项 | E021 §7.2 |
| 评价 | 学员评讲师 + 讲师评学员**双向**，由调查中心提供 | E021 §7.1 |

**异常路径**：
- 超出签到时间范围 / 位置不在电子围栏内 → 签到被拒
- 学员请假获批 → 不计缺勤，不出现在催促名单
- 选「满足所有条件」但成绩未录入 → 学员面授未完成

## 4b.3 调查闭环 📋 需求池
```
① 选类型          ② 设基本信息      ③ 编题          ④ 配规则        ⑤ 发布收集      ⑥ 看结果
问卷/投票/报名/评价 → 名称+分类+起止 → 30种题型+逻辑 → 积分/作答/参与/消息 → 收集(可配额) → 统计与导出
```

| 环节 | 关键规则 | 证据 |
|---|---|---|
| 类型 | **问卷调查 / 投票评选 / 报名登记 / 评价满意度** 四类 | E020 §2 |
| 编题 | **30 种组件**；**逻辑设置支持条件跳转**；选项可分组 | E020 §3.2/3.3 |
| 参与 | **匿名** 与 **游客** 是两个正交开关 | E020 §3.4 |
| 结束 | **收集多少份结束** → 收集状态停止，状态仍为已发布 | E020 §3.4 |
| 接入 | 被面授评价、项目调研、报名等多场景调用 | 手册 |

**异常路径**：
- 达到收集配额 → 第 N+1 人打开提示已结束
- 允许重复作答 + 积分"只有第一次可获得" → 重复作答不重复发积分

# 五、跨模块依赖图

```
组织 ──┬──> 人员 ──┬──> 角色权限（多对多）
       │           ├──> 直属经理 ──> 主管数据范围
       │           └──> 学习记录
       │
分类 ──┴──> 分类权限矩阵 ──> 课程可见范围
             │
课程 ────────┴──> 任务（必修/计入完成度/时长/学分）
  │                │
  └──> 项目 ───────┘
        │
        ├──> 指派规则（部门/岗位/入职时间）──> 组织、人员
        └──> 学习记录 ──> 统计报表
```

## 批次 7/8 新增的强依赖
6. **调查中心是横向能力**，被面授评价、项目调研等调用 → **必须先于依赖它的模块完成**（批次 8 内部排序：调查 → 面授）。
7. **面授的「录入面授考核成绩」** → 面授学员记录需有成绩字段与录入人，早于完成标准判定。
8. **考试与项目任务联动** → 批次 7 的考试对象须能被批次 4 的项目任务引用。

## 强依赖（不可绕过）
1. **课程可见范围依赖分类权限** → 分类权限模型必须先于课程开发。
2. **指派规则依赖组织与人员的部门/岗位/入职时间** → 人员档案字段必须先完备。
3. **主管数据范围依赖「直属经理」字段** → 该字段不可省略，否则主管角色无法实现。
4. **统计依赖学习记录的快照字段** → 记录设计错误将导致报表无法复现。
5. **项目完成度依赖任务的"是否必修"与"是否计入完成度"两个独立属性** → 二者合并会导致完成口径无法实现。
