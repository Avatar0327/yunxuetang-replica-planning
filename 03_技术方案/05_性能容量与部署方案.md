# 性能容量与部署方案

版本：v1.0 设计定稿｜更新：2026-09-23。所有硬件、延迟与恢复时间数字均为**设计/压测起点，尚未实测、未采购、未部署**。

## 1. 负载口径

5 万人员是名册规模；1 万同时在学是活跃学习会话规模；API并发请求数、每秒请求数、媒体并发分别度量。大规模考试本期不纳入容量承诺。

| 负载 | 可复算假设 | 估计 |
|---|---|---|
| 平均学习上报 | 10,000活跃会话 ÷ 20秒 | 500请求/秒 |
| 上报压力起点 | 平均值3倍；集中恢复、卸载、开课另测 | 1,500请求/秒突发，不代表真实峰值上限 |
| 连续8小时上报量 | 500 × 3,600 × 8 | 1,440万次/日 |
| 原始上报体积 | 若每条1KB，未含索引、WAL、复制 | 约14.4GB/日；30天约432GB |
| 视频出口 | 10,000 × 2Mbps | 20Gbps，约9TB/小时、72TB/8小时（十进制） |
| 视频敏感性 | 每人1～4Mbps | 10～40Gbps；实际按观看人数/码率/时长计费 |
| 媒体逐请求鉴权 | 假设每2秒取一片段，10,000人 | 约5,000鉴权请求/秒，另加清单/密钥/重试；分片策略会改变此值，不能算进500次心跳后就忽略 |
| 项目状态规模 | 50,000人 × 人均20项目（测试假设） | 100万参与记录 |
| 任务事实规模 | 上述每项目20任务（测试假设） | 2,000万任务记录，不声称业务已确认此均值 |

视频字节不经过Nest API：首选CDN每请求鉴权回调中央authz；供应商不支持时使用Nginx受控媒体网关的鉴权子请求＋对象存储字节代理，Nest只返回授权结果。网关带宽需独立覆盖10～40Gbps估算并压测；未验证该通路不能以纯签名URL上线。CDN出口与对象存储回源单独限额、告警、核算费用；“API扛500请求/秒”不能证明媒体体验合格。普通列表/详情、登录、任务读取、完成交易、导出、每日指派和02:00扣减要与学习上报一起压测。

## 2. 初始部署与容量扩展

建议使用同区域托管组件，前端静态资源与媒体均由CDN交付。后端一个版本的制品以API和后台两种运行模式发布，不引入独立业务服务。

| 组件 | 压测起步资源建议 | 扩展/可靠性 |
|---|---|---|
| API | 2实例，每实例4vCPU/8GB | 无会话粘滞要求；确认数据库连接预算后横向扩展 |
| 后台任务 | 1实例4vCPU/8GB；媒体转码另限并发 | 可增副本，任务租约+fencing/幂等防重复执行；媒体任务避免挤占账务任务 |
| PostgreSQL | 8vCPU/32GB、SSD、主备高可用 | 常规自动切换采用同步复制并验证ACK持久性；先看索引/锁/WAL/IO，再升级资源；本期不默认分库；汇总查询用report投影 |
| Redis | 2～4GB容量起测、托管主备 | 只承载可恢复数据；淘汰策略不能误删单活协调键，缓存与任务用途分实例或策略隔离 |
| 对象存储/CDN | 私有桶、分片上传、签名访问 | 压测签名验证/缓存命中/回源，并确认带宽与预算 |
| 日志/指标 | 集中采集、分级采样 | 记录traceId，不记录密码、会话cookie、完整身份证和媒体签名 |

数据库连接总预算：API副本数×每实例池上限＋后台池＋迁移/管理预留，必须小于数据库安全连接上限。初始可从每API实例20连接、后台10连接起测；不随进程数无上限扩大。数据库繁忙时限流/排队，不通过无限重试放大故障。严格媒体撤权需要边缘逐请求核对当前授权版本，纯TTL缓存不满足此要求；鉴权子请求可使用单体制品的受限入口独立扩副本，但不复制授权规则。上表资源只是起测点，不能凭500次学习上报推定也能承载数千媒体鉴权请求。

存储预算须实测“原始上报＋ACK摘要＋业务事实＋outbox各订阅交付/inbox＋索引＋WAL”，不能把14.4GB/日原始报文量当成数据库总增长。初始压测建议预留至少1TB可扩展SSD，使用30天代表性历史数据测行宽和放大倍数；若不足则调整存储或归档窗口，不默删永久事实。上报HASH分区、跨日去重、事件流序号、归档与作业恢复协议见[09](09_技术决策与运行细化.md)。

客户隔离已按T-07/T-15定案；生产云平台、区域、域名/TLS与采购预算在部署前确定。本轮没有云资源写入和成本支出。

## 3. 写入路径与一致性

### 学习上报

- 浏览器约20秒上报，加入小幅随机抖动避免整点洪峰；单会话序号递增，重试复用原幂等身份。
- 请求经身份、课程状态、时间窗、单活会话及范围校验；服务器使用可验证的耗时增量，拒绝不合理跳变和复用会话。
- **返回接受成功前，输入必须已持久化。** Redis故障不得导致已经确认的进度消失。允许微批写入，但批窗口必须计入响应时延，并保证每条可独立确认/重试。
- 当前进度、确认过的时间区间和完成权益使用紧凑状态；审计/争议所需明细另行分区。累计时长以真实接受的行为累加，有效时长封顶；乱序与重复不重复计数。
- raw上报、业务事件、永久学习结果的保留周期分别配置；热数据压缩/归档策略需评审。不能为了降写入量丢失幂等和争议追溯依据，也不假设每个心跳永久保留。
- 正常关闭用visibilitychange/pagehide和可用的sendBeacon/keepalive补报，本地保存未确认事件并在下次打开重试。浏览器强杀、设备损坏和永久断网不具备绝对零丢失保证，AC-E-04的环境范围见决策登记。

### 完成与奖励

完成判定独立于时长统计投影，不能从延迟报表字段反推。学分即时发放按持久完成事实、权益幂等键和账户串行化处理，不等待项目10分钟进度投影。余额与待抵扣双金额守恒；T-11/T-15完整奖再按同人同公司同币种抵扣，恢复/重试不重复发奖或扣减。课程与项目资格按T-19分别去重；issuer_control每公司/币种固定64分片，个人账户仍唯一，避免单个控制账户串行化全部完课；对账合并全部控制科目分片验证守恒。

任务队列丢失可用outbox与待结算记录重建。周期指派以项目/公司/人员/轮次唯一约束去重；次日02:00按业务时区选到期记录，具有批次ID、检查点、漏跑补偿与重入保护，不因进程重启漏扣或重扣。

### 大纲变更

普通任务进度的10分钟展示刷新，不覆盖D-42“生效后分母立即重算”的要求。预计算可异步，生效是有明确一致性边界的动作。准备期间旧版本有效；所有受影响查询和完成/奖励计算切换到同一生效版本。

基准测试至少覆盖一个项目1,000/10,000/50,000参与者、并行学习更新和同公司跨项目共享学分账户，并混入跨公司不可抵扣账户。观察预计算时长、屏障时长、账户争用、管理员确认后等待时间；无法保持一致时本次发布不生效并可重试，不能部分生效。终态屏障超时阈值建议2秒作为探索目标，**未验证前不写成承诺**；超出目标须优化或提请调整发布流程。

## 4. 读路径

组织树建议邻接关系＋闭包表，部门最多20级；分类树最多10级。人员列表按租户/公司/状态/主部门/岗位/直属经理/入职时间建立常用组合索引，索引选择以真实查询EXPLAIN为准。

鉴权生成ScopeSpec后在数据库过滤，过滤在排序、分页和count之前。中央PolicyCompiler负责语义；跨模块人员范围通过OrganizationPublic取得绑定授权版本的许可集合/关系快照，在report本模块SQL中前置过滤，不JOIN组织私表。许可关系只可在版本不变时复用；当前账号状态变化也使其失效。禁止每行查询人员权限的N+1模式。API限制页大小、字段选择和排序白名单，大范围导出转异步；导出开始、执行和领取均复核权限。

report拥有独立读模型，记录部门/岗位历史快照，当前账号状态和当前授权范围使用权威版本或新鲜校验。浏览/学习/完成三态、人次/人数、指派/自主分别记录；分母零显示`--`。缓存键必须包含租户、用户/有效范围及公司上限、授权版本、筛选与数据版本，不能共用管理员缓存给主管。

## 5. 五层时效与可观察性

| 数据 | 业务要求 | 技术处理与展示 |
|---|---|---|
| 进度上报 | 约20秒节流 | 显示已确认进度；本地未确认状态不能冒充服务器确认 |
| 项目任务进度 | 每10分钟 | 定时增量投影，显示更新时间；D-42发布绕开旧投影并使用新生效结果 |
| 奖励 | 即时 | 完成确认链路同步落账；建议健康状态P95≤2秒作为待验目标，不从十分钟报表取余额 |
| 汇总看板 | T-1 | 按Asia/Shanghai自然日结算，只展示已成功结算日期；失败不写0、不假称最新 |
| 逾期扣减 | 次日02:00批处理 | 02:00启动，记录进度/结束时间；“02:00后”具体结算完成上限需与业务验收约定 |

明细报表准实时，建议健康状态下60秒内完成投影作为待验目标；字段展示明确是有效学习时长。AC-E-02允许短暂未更新，与AC-E-21禁止长期端间口径不一致同时成立，不能拿“延迟允许”掩盖投影故障。

监控至少包含：HTTP P95/P99/错误率、事件循环延迟、池等待、慢SQL、锁等待、WAL/磁盘、Redis命中/故障、outbox年龄、任务重试/死信、进度积压、发奖延迟与账务差额、扣减完成时间、CDN命中和回源、媒体首帧及卡顿。

## 6. 压测计划与建议门槛

全部门槛待实际环境确认；测试报告记录资源、数据量、接口比例、权限分布、结果与瓶颈。不能只测试超管或缓存命中场景。

| 测试 | 输入 | 初始验收目标/必须观察 |
|---|---|---|
| 权限预研微基准 | 5万人、20级组织、六范围、多角色、跨部门直属经理、公司隔离及跨客户授权 | SQL无全表拉回/N+1；范围/公司过滤与分页计数一致；共享项目不泄露其他公司；不代替全平台压测 |
| 稳态混合负载 | 1万会话、500上报/秒，加真实比例列表/登录/完成 | 上报P95≤300ms、P99≤1秒；普通API P95≤500ms、P99≤1.5秒；非预期限流错误率<0.1%（建议目标） |
| 突发恢复 | 上报1,500/秒起测、集中开课/重连/补报 | 无已确认写入丢失、无重复奖励；记录可持续上限和恢复耗时 |
| 长稳 | 8小时稳态、期间批处理/导出/部署 | 无持续内存增长、无无法追平的积压、连接/索引体积可控 |
| 热点完成 | 同课程万人近同时完课、账号同时触发不同项目、同公司控制账户分片热点、跨公司欠项 | 唯一权益与余额账务正确，锁不形成全站串行瓶颈 |
| 大纲重算 | 1千/1万/5万人及跨项目账务竞争 | 新旧版本无混读，影响提示与最终提交一致，取消无副作用 |
| 故障 | Redis断开、API重启、worker终止、同步复制主备切换、媒体失败 | 已确认事件可恢复；权限不降级放行；重启不重复指派/发奖/扣减；全区域灾难另按RPO测试 |
| 安全与媒体 | 普通学员/主管、撤权、下架、尚未过期签名、CDN命中与回源；媒体鉴权负载独立增加 | 若声明下一媒体请求失效，须逐请求版本/状态校验；纯短签名不足以通过；已下载字节不宣称可撤回 |

功能不变量（零越权、零重复权益、账务守恒、新旧大纲一致）比吞吐数字优先；通过延长缓存、跳过鉴权、延迟即时奖励得到的吞吐不算通过。

## 7. 发布、备份与恢复

数据库迁移走expand/contract：先兼容扩展，再发布读写新版本，完成回填与验证后再清理旧结构；禁止生产启动自动执行破坏性迁移。前后端契约保持滚动发布兼容窗口，任务进程遵守事件版本。

发布顺序：备份与恢复点检查 → 迁移预演 → 兼容迁移 → API/worker滚动更新 → 静态前端发布 → 核对登录、权限、学习、发奖、投影和定时任务。回滚优先回滚应用到兼容版本；已产生业务数据不能靠盲目回滚数据库覆盖。

建议启用PostgreSQL连续WAL备份/PITR、每日备份、对象版本/误删恢复和独立备份访问权限；数据库与媒体元数据恢复需保持引用一致。普通同步主备切换以不丢已确认事实为目标，必须测实际托管配置及故障切换；异步备库强制提升不能冒称零丢。**全区域灾难、误操作等依赖备份恢复的场景，建议RPO≤5分钟、RTO≤60分钟作为待确认运营目标**，这允许备份窗口内的数据损失，不能与正常ACK保证混用。若账务要求灾难下也零丢，需另选同步容灾并评估成本。Redis丢失可从权威存储恢复缓存、任务及会话协调；不依赖Redis备份挽救已确认账务。

## 8. 成本与上线限制

预算由API/DB/Redis固定资源、媒体存储、CDN流量、转码、日志与备份构成。媒体可能主导费用，应在采购前按真实码率、日学习小时和峰值人数核算；本方案不提供未经供应商报价核验的金额。

名册靠人工维护、站内触达率低仍是业务风险。性能优化不等于解决这两项风险；不自动加入北森/飞书/钉钉。四项最简实现与永久缺口仍见总索引，容量通过不能将G-01/G-02/G-04/G-05/G-06标为原站已验证。
