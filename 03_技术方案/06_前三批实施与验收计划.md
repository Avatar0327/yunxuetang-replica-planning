用户确认技术栈及已记录T系列口径 → 技术方案v1.0业务审核通过 → 交付物A已审核、B已放行 → v8.3输入重新基线化完成 → 三天权限预研 → 回填框架适配结论及工期 → B1 → B2双轨 → B3。已确认决定不重复索要；预研已交付No-Go，实际矩阵与性能见12，正式B1实现仍未开始。公司隔离为B1授权基础，不推迟至报表阶段补做。

任何原型和代码都在交付设计之后。本轮只写文档；三天不是本次对话中假装已经消耗的时间，也不以框架README或静态设计代替可运行验证。

三天预研详见04。若需自研，输出新增模块、测试范围、上下限和对B1-08的影响；B1-05＋B1-07原8～13人天不能自动沿用。预研3天先单列，实际可复用成果再核对是否折抵，避免重复计价。

### 2B

2. 两种时间模式、每人计划起止、跨度可配置规则、项目完成口径配置；不在空大纲上伪造完成闭环。

4. DIFF-15与B2-13/14已确定用户组四维及动态组联动；B4-07明确旁听/正式互转。补齐组管理、来源记录与版本事件的技术任务，联动按T-14多来源/原轮次恢复，转换奖励按T-19。主管增删受项目开关、直属团队及公司范围约束，真实合流验收在B4完成。

**出口**：管理员能建课并发布、创建两类项目和指派人员，重复提交/重复指派不重复。AC-N-01/06、AC-R-01/02/03及分类权限、隐藏、下架、标签治理可演示；AC-N-02中挂载大纲、学员端呈现等分支需等B3/B4，不提前标全通过。

## 5. B4与后续不能丢失的顺序
