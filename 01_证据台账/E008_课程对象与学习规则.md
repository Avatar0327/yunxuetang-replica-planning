## 3. 课程创建表单 — 步骤1【已验证，全字段】

### 3.1 基本信息
| 字段 | 类型/约束 | 原站说明文案 |
|---|---|---|
| 名称 | 文本，**上限 200 字** | — |
| 分类 | 引用，支持「新增分类」 | — |
| 封面 | 图片，「设置封面」 | — |
| **价格** | **积分** | 「设置积分后，学员需要使用相应的积分兑换后方可学习」 |
| **标签** | 多值 | **「学员完课后将自动获得关联的标签」** |
| 简介 | 文本，**上限 2000 字** | — |
| 附件 | 文件，**最多 50 个** | 「学员观看该课程时可以下载附件，支持类型：视频/音频/文档/图片/压缩包」 |
| 编码 | 文本 | 业务编码 |
| **版本** | 文本 | **课程具备版本字段** |

**【已验证】两条重要业务规则**：
1. **课程可设积分价格**，学员需用积分兑换后方可学习 → 「可学习」有**前置条件**，不只是权限。
2. **完课自动授予标签** → 标签既是人员分类维度，也是**学习成果的载体**；完课行为会反向修改人员属性。这对「完成」的定义与副作用极其重要。

### 3.2 相关方信息
| 字段 | 说明 |
|---|---|
| 贡献者 | 自动填充当前操作者（实测：`管理员(admin)`） |
| 作者 | **最多 10 个**（`+ 新增（0/10）`） |
| 主讲老师 | 引用师资 |
| 辅讲老师 | 引用师资 |

【已验证】课程的「人」有 4 种角色：贡献者（系统记录）、作者、主讲、辅讲。

### 3.3 权限设置【已验证】——直接回答「可见范围」
| 字段 | 选项/说明原文 |
|---|---|
| **是否隐藏** | 「设为隐藏状态（**仅在课程或项目中使用**）」 |
| 分享权限 | 「允许ta人分享」 |
| **浏览权限** | ① **跟随分类浏览权限**　② **单独设置允许浏览** |
| **游客访问** | 「支持游客访问」 |

**【已验证】可见范围模型（关键）**：
- 课程的浏览权限**默认继承自「分类」**，也可**单独覆盖** → 可见范围是**分类级继承 + 课程级覆盖**的二级模型。
- 「隐藏」不等于「无权限」：隐藏课程**仍可被课程或项目引用**，只是不在自主浏览场景出现。
  → 这正是「指派学习」与「自主学习」分离的实现基础（呼应 E007 §3）。
- **游客**是一等公民身份，课程可对游客开放。

### 3.4 功能设置【已验证】——直接回答「播放/进度/时长」
| 字段 | 说明原文 |
|---|---|
| 完课评论 | 「开启完课评论弹窗」 |
| 讨论区 | 「开启讨论区」 |
| 笔记区 | 「开启公开笔记区」 |
| **倍速播放** | 「开启倍速播放（开启后，学员可以切换 1.25/1.5/1.75/2 倍速播放视频）」 |
| ⭐ **学时计算** | **「倍速播放时学习时长也倍速计算（举例：学员2倍速学习5分钟，学习时长计算10分钟）」** |
| ⭐ **拖拽学习** | 「支持拖拽学习」 |

**【已验证】两条高价值规则**：
1. **学习时长 ≠ 实际观看墙钟时间**。开启该项后，2倍速看5分钟计为10分钟学习时长（按**内容时长**而非**真实耗时**计）。这是「学习时长」口径的决定性规则，**必须写入指标字典**。
   - **风险提示**：此规则可被学员利用（开2倍速刷时长）。目标产品是否保留需用户决策 → **DIFF-09**。
2. **拖拽学习是课程级开关**。关闭时学员无法拖拽进度 → 直接对应规划要求中「拖拽进度是否计入」的问题：原站的做法是**从源头禁止拖拽**，而非「允许拖拽但不计进度」。

## 4. 课程创建表单 — 步骤2：学习内容设计【已验证】

独立子应用 `/ulcd/`（learning content designer），顶栏：`← <课程名>` / `解锁模式选择器` / `暂存关闭` / `保存`

### 4.1 课程结构【已验证】
创建时强制二选一：
- **无章节**：「学习任务较少时，可以使用无章节，所有任务将平铺展示」
- **有章节**：「学习任务较多时，可以使用章节将任务组织分类，方便学员按章节进行学习」

另有结构类型：**课程 / 直播 / 面授** 三类。

### 4.2 任务类型清单【已验证】
课程由**任务(Task)** 组成，可添加的任务类型：

| 分组 | 类型 |
|---|---|
| 在线任务-内容 | 文档、视频、音频、微课、**scorm**、**html**、**外链课** |
| 互动/考核 | **练习**、**考试**、讨论、问卷、**签署** |
| 实操 | 在线任务、**作业**、**实战演练** |
| 上传 | 本地上传、上传课件 |

**【已验证】课程 = 任务容器**，「课程完成」必然是**任务完成状态的聚合**，不是单一视频的播放进度。
→ 这是「打开页面 / 播放内容 / 记录进度 / 课程完成」四态区分的结构性基础。

### 4.3 任务对象字段【已验证】
任务列表表头：`类型` / `名称` / **`学分`** / **`时长`** / `状态` / `操作`
→ 【已验证】**学分与时长是「任务」级属性，不是课程级**。课程的学分/时长应为任务的聚合。

### 4.4 ⭐ 解锁模式（学习顺序规则）【已验证】
| 模式 | 说明原文 |
|---|---|
| **自由学习模式**（默认） | 「不设学习限制，学员可以在任何时间学习」 |
| **按顺序学习**（闯关） | 见下方配置 |

「按顺序学习」的子配置：
- **不参与闯关的任务类型**：话术训练 / 演讲训练 / 实战演练（多选，**默认不勾选＝全部参与闯关**）
  > **原文：勾选后，所选类型的任务不参与闯关解锁：既不作为解锁下一关的前置，自身也不被前面关卡锁住，学员可随时学习。不影响该任务是否必修及是否计入项目完成度。默认不勾选（全部参与闯关）。**
- **解锁单元**：`按内容`（默认） / `按章节`

### ⭐⭐ 本次调研最重要的规则发现【已验证】
上述原文明确区分了**三个正交概念**：

| 概念 | 含义 | 是否互相影响 |
|---|---|---|
| **闯关解锁** | 任务能否被访问（顺序约束） | 独立 |
| **是否必修** | 任务是否必须完成 | **不受闯关配置影响** |
| **是否计入项目完成度** | 任务是否参与完成率计算 | **不受闯关配置影响** |

**规划含义（必须写入需求基线）**：
「可访问性」「必修性」「计入完成度」是**三个独立的任务属性**，目标产品不得将其耦合为单一的「必修/选修」开关。
这是原站经过打磨的设计，**建议直接复刻**。

### 4.5 协同编辑【已验证】
页面底部显示「**等0人也正在编辑该内容**」→ 原站支持**多人同时编辑同一课程内容并提示并发**。
- V1（单闭环 MVP）不做，但需在需求基线中登记为**已知的并发冲突场景**。

### 4.6 保存机制【已验证】
顶栏提供 `暂存关闭` 与 `保存` 两个动作 → **草稿态与正式保存分离**。

## 8. 追加发现：课程创建入口的重复提交缺陷【已验证】

### 现象
通过 URL `/kng/#/operator/course?id=<已存在课程ID>` 访问时：
- 页面标题显示 **「创建课程」**（非「编辑课程」）
- 表单**预填了已存在草稿的数据**（名称「未命名课程」、分类「走进企业大家庭」、已设封面）
- 修改名称后点击「下一步」，系统**新建了一门课程**（新 ID `4531aa1f-fe9e-4922-ad6a-9c2d2fd88b93`），而非更新原草稿
- 结果：课程列表从 2 条变为 **3 条**，出现内容重复的两门草稿

### 【已验证】结论
1. `/kng/#/operator/course` 路由**始终是"创建"语义**，不承担编辑；`id` 参数不被用作编辑目标。
2. 该路由会**预填上一次未完成的草稿数据**，造成"看起来是在编辑"的错觉。
3. 「下一步」**同时承担"提交创建"职责**，且无二次确认、无防重复提交保护。

### 规划含义 —— **DIFF-10（原站缺陷，明确不复刻）**
这是典型的**原站缺陷，不得转为目标产品要求**：
- 目标产品必须**明确区分创建与编辑路由**，编辑路由以资源 ID 为准并显示「编辑」语义标题。
- 「下一步」类的分步表单按钮**不应承担隐式创建**；应显式区分「保存草稿」与「下一步」。
- 需有**防重复提交**保护（幂等键或提交锁）。
- 验收场景：`重复操作` 类必须覆盖「连续两次进入创建流程不应产生重复对象」。

### 补充字段证据【已验证】
从编辑/创建表单实际渲染中补充：
- `名称` 为**必填**（红点标记）
- `分类` 为**必填**（红点标记），实测值示例「走进企业大家庭」
- `价格` 默认值 **0**（积分）
- `标签` 输入方式：**「请输入标签内容，点击回车创建」** → 标签为**自由文本、回车即创建**，无预置词表约束
  - 【规划提示】自由创建标签易产生同义标签泛滥；结合「完课自动获得标签」的规则（§3.1），标签会直接写入人员属性，**建议目标产品对标签做受控词表**。列入 DIFF-11。
