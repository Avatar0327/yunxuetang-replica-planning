### ⭐⭐ 直接回应「打开页面/播放内容/记录进度/课程完成/项目完成」的区分要求
原站在此对象上用**三组独立字段**表达学习状态，证明五态区分在原站是真实存在的：

| 维度 | 字段 | 说明 |
|---|---|---|
| **是否开始** | `完成状态` = 未开始 / 学习中 / (已完成) | 「未开始」与「学习中」分离 |
| **开始的两种时间** | `计划开始学习时间` vs `实际开始学习时间` | **计划 ≠ 实际**，周期模式下尤其关键 |
| **最近活动** | `最近学习时间` | 独立于开始与完成 |
| **进度的三路计算** | `项目完成进度` / `必修进度` / `选修进度` | 必修与选修**分别计算**后再聚合 |
| **逾期** | `逾期状态` | **与完成状态正交**——可以「学习中且已逾期」 |
| **结果** | `得分/结论` | 完成之外还有成绩与结论 |

**规划含义（必须写入需求基线与对象字典）**：
- 学习记录**不是一个 0/1 的完成标志**，至少需要：完成状态、逾期状态、三路进度、四个时间戳、得分与结论。
- **必修进度与选修进度必须分开存储**，否则无法支持 E010 §1 的两种项目完成口径切换。
- `账号状态`、`部门`、`岗位` 在记录中**冗余展示** → 提示原站在记录上保留了人员快照信息（或实时关联）。**这是解决 E007 §2「禁用人员统计消失」问题的技术前提**，需在 V-35 确认是快照还是实时关联。

## 3. ⭐ 周期模式下的学员开始时间【已验证】
点击「添加学员 → 正式学员」后，**第一个必填项就是「开始学习时间」**（默认当前时刻，实测预填 `2026-09-21 01:08`）。

**【已验证】** 在**周期模式**项目中，**每个学员的学习周期从其个人「开始学习时间」起算**（本项目周期 365 天）。
→ 这印证 E009 §2.1，并说明：
- `计划开始学习时间` 即此处设定值
- `实际开始学习时间` 为学员首次真实学习的时间
- 两者分离是周期模式的必然产物

**规划含义**：学习有效期的计算必须以**学员维度**而非项目维度存储起止时间。目标产品若只存项目级起止日期，**无法支持周期模式**。

### 4.1 编辑加入规则（对话框全字段）

### 【已验证】指派范围的完整维度
**4 个维度 + 1 个逻辑运算符 + 定时执行**：
1. **部门范围**（多选，支持组织树层级）
2. **岗位范围**（多选）
3. **用户组范围**（多选）
4. **入职时间**（可限制区间 / 不限）
- 组合方式：**任意条件(OR) 或 所有条件(AND)**
- 执行：**每天定时扫描**，符合条件者自动加入

### 【已验证】重要的否定结论
**「标签」不是指派维度**。虽然标签是人员的重要分类维度（E005/E008：完课自动打标签），但**项目自动加入规则中没有标签范围**。
→ 规划时**不得想当然地把标签加入指派维度**；若目标产品需要，属于**新增需求**而非复刻。列入 **DIFF-15**。

### 4.2 关联动态用户组
第二条自动加入路径，呼应 E009 §2.4 的「动态用户组删减人员，自动同步到项目中」。
→ 【已验证】指派范围可**双向动态维护**：规则扫描（每天）+ 动态用户组联动（实时或近实时）。
- 【未验证】两者优先级与冲突处理 → **V-36**
