## 1. 权限模型结构【已验证】——三维模型

原站角色权限**本身就是三维定义**，与规划要求的「功能操作 / 数据范围 分别描述」高度吻合：

| 维度 | 列名 | 含义 |
|---|---|---|
| ① 导航可见性 | **导航** | 该角色能否看见此菜单/页面（单个勾选框） |
| ② 功能操作 | **操作权限** | 该页面内可执行的具体操作（多个勾选框，部分带「详细权限」二级展开） |
| ③ 数据范围 | **数据范围** | 每个节点独立的「设置数据权限」入口 |

**【已验证】关键结论**：数据权限是**按节点单独配置**的，不是角色级的一刀切。同一角色在不同报表/模块上可以有不同的数据范围。
→ **规划含义**：目标产品的权限模型至少需要 `角色 × 功能节点 → {导航, 操作集, 数据范围}` 三元组，不能简化为「角色→权限点」的二维模型。

## 2. 权限作用域分为两个页签【已验证】
- **基础功能**：平台级能力（平台运营、我的企业、报表中心、安全中心、日志管理、档案中心、开放平台等）。共 **441** 个勾选项。
- **企业应用**：按**应用**分别授权。先在应用宫格中勾选授予哪些应用，再逐应用配置其 导航/操作权限 树。
  - 应用宫格含：培训中心、培训规划、在线课堂、测练中心、师资管理、社区管理、直播中心、面授中心、游戏中心、AI对练、智慧门店、AI知识助手 等（与 E004 模块清单一致）

### 角色分级与分类的含义
- 【已验证】存在 **1/2/3 三级角色层级**，1级最高（平台管理员、运营负责人）。
- 【已验证】角色分 **系统角色** 与 **业务角色** 两类。业务角色多为带部门/岗位语义的职能角色（督导、店长、店员、导师、项目负责人）。

## 4. 关键角色权限实测【已验证】

### 4.1 普通学员（127人）
- **基础功能：441 个勾选项中 0 个勾选**
- **【已验证】学员在管理端拥有零权限**，完全不可见管理控制台。
- → 目标产品可直接采用同样基线：学员端与管理端彻底分离，学员无任何管理入口。

### 4.2 平台管理员（16人，1级系统角色）
- 角色描述原文：**「超级管理账号身份，拥有管理账号、配置角色等高级权限。」**
- 基础功能：**59/441 勾选**，集中在 34 个节点，全部位于 `平台运营(个性化装修/登录/电脑端)` 与 `报表中心`。
- 企业应用（培训中心）：**33/33 全勾选**（项目中心、项目管理、项目集管理、外派培训、培训分类、模板库、项目模板、鉴定模板、作业模板、设置）
- ⚠️ **【受限验证】矛盾点**：角色描述声称「拥有管理账号权限」，但基础功能中 `我的企业→员工名册` 的勾选项**未被勾选**。
  - 可能解释A：平台管理员为特权角色，部分权限硬编码不体现为勾选项；
  - 可能解释B：真正的全权身份是**超管**（员工名册行操作中存在 `设置超管`/`取消超管`），与角色体系并行；
  - **列为 V-16，需登录 zhaoxuejiao（平台管理员）实测其可见菜单才能定论。**
  - **规划含义**：在此定论前，不得断言「平台管理员 = 全权管理员」。

## 5. 敏感字段级权限【已验证】——重要且可直接复用的规则

在**所有含个人维度的报表节点**上，以下三项作为**独立的操作权限勾选项**反复出现：
`身份证号`、`邮箱`、`手机`

另有 `查看游客数据`、`查看外部讲师` 等作为独立权限项。

**【已验证】结论**：原站将**敏感字段的可见性下沉为字段级权限**，与页面访问权限分离。一个角色可以看报表但看不到身份证号。
→ **强烈建议目标产品保留此设计**（即使 V1 不实现，数据模型需预留）。列入需求基线。

## 6. 报表目录【已验证】——交付物5 指标字典的范围依据

报表中心的完整统计域（来自权限树）：
- **使用总览** / 系统使用情况（平台活跃统计、APP安装统计）
- **学习结果统计**（部门维度 / 个人维度 / 岗位维度）
- 讲师教学统计（讲师统计）
- **项目统计**（项目参与情况[部门/个人维度]、项目完成结果、任务完成详情、个人完成详情）
- 带教结果统计（导师带教结果、学员学习详情）
- 项目集完成结果（项目完成详情、个人完成详情）
- 培训计划统计（部门实施情况、计划完成情况）
- 面授统计 / **课程统计**（学习统计[部门/个人维度]、课程学习详情、个人学习详情）
- **考试统计**（考试参与情况、考试结果统计、小题作答详情、个人作答详情、循环考试结果[批次作答详情]）
- 练习统计 / 调查统计 / 直播统计 / 证书统计 / 话术训练统计
- **数据大屏**（平台总览、活跃详情、项目详情、考试详情、课程详情）
- 报告助手（运营报告）

**【已验证】统计维度的通用模式**：几乎每个统计域都按 `参与情况(部门维度/个人维度)` + `结果统计(明细)` 两层组织。
→ 目标产品报表设计可直接沿用此两层结构。V1 只需 **课程统计 → 学习统计(个人/部门维度) + 课程学习详情**。

## 7. 其他平台能力（来自权限树，仅登记不展开）
- **档案中心**：员工档案、培训档案、外训档案、考试档案、练习档案、调查档案、导入档案
- **安全中心**：账号安全、数据安全（水印控制、IP白名单、防截屏/录屏、信息设置、聊天设置、下载设置）、站点安全（保密协议、护网设置、签名证书上传）
- **日志管理**：操作日志、登录日志、消息日志（均可导出，均可设数据权限）
- **合规管理**：评论管理、举报管理、敏感词管理、舆论管理、禁言管理
- **激励体系**：经验值、积分、学分、时长、勋章（各自含 规则设置/管理/调整/清零）
- **证书管理**：创建/编辑/删除/颁发/吊销证书、查看获得证书人员、导出
- **报名管理**：发起报名、添加名额、二维码、导出

**【已验证】原站的激励体系是四套并行的**：经验值 / 积分 / 学分 / 时长，各自独立的规则、管理、调整、清零。
→ V1（单闭环 MVP）**不做**任何一套，但需在业务对象字典中登记，避免 V2 返工。
