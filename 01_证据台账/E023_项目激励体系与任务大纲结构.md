## 2. ⭐ 任务大纲是**三层结构**【已验证】

```
阶段1  启动会+基础知识学习          ← 阶段（有名称、有描述、有奖励）
  「企业基础知识的学习」            ← 阶段描述
  ├ 【考勤】开班签到                ← 任务（直挂阶段下）
  ├ 【活动】开班仪式
  ├ 【投票】小组表现投票
  ├ 【活动】公司参观介绍
  └ 基础知识学习                    ← ⭐ 分组（有名称、无奖励、纯归类）
      ├ 【文档】企业发展历程
      ├ 【文档】企业价值观
      └ …
```

### 结论（对 D-25 的实证修正）
- 原站实为 **阶段 → 分组 → 任务** 三层，且：
  - **阶段**：有名称、有描述、**有独立奖励**
  - **分组**：有名称、**无奖励**，是纯粹的视觉归类层
  - **任务**：奖励的基本单位
- **任务可以直挂阶段，也可以挂在分组下**——两者在同一阶段内混排。
- → 数据模型上，分组是 `阶段` 下的**可选中间容器**，不是必经层级。

## 3. ⭐⭐ 激励体系：**双币种 × 五级发放 × 九类触发**【已验证】

### 3.1 页签结构
`任务大纲` | `学分/积分设置` ——后者下分 **`奖励规则`** / **`扣减规则`** 两个子页，另有 **`必修学分规则说明`**。

### 3.2 ⭐ 系统预计算奖励上限
> **「当前设置下，本项目学员有机会获取 340 学分 355 积分」**

**原站会实时汇总整个项目的奖励天花板并展示给管理员。** 这是很好的设计——管理员配奖励时能立刻看到总量，避免通胀。**建议复刻。**

### 3.3 ⭐ 同步模式二选一
> **`自动同步学分`** / **`手动同步学分`**

学分发放存在**自动/手动**两种模式开关。（未验证其切换后的具体行为差异 → 见 §7）

### 3.4 ⭐ 五级发放层次（奖励规则）

| 层级 | 规则原文 | 样本值 |
|---|---|---|
| **项目级** | 完成所有选修和必修后，获取 X 学分 | 10 学分 |
| | 完成所有选修和必修后，获取 X 积分 | 20 积分 |
| **评优级** | **优秀学员**可获取 X 学分 Y 积分 | 20 学分 30 积分 |
| **带教级** | 学员每次获得的评价为**合格**时，获取 X 学分 Y 积分 | 0 / 0 |
| | 每次获得的评价为**不合格**评价时获取 X 学分 Y 积分 | 0 / 0 |
| **阶段级** | 选修和必修 完成后，获取 X 学分 / Y 积分 | 每阶段 10 学分 10 积分 |
| **任务级** | 见 §3.5 | 因类型而异 |

> ⭐ **学分与积分是两个完全独立的字段**，同一任务可配不同值。
> 实证：`基础知识考试` = **20 学分 / 30 积分**；`结业考试` = **30 学分 / 15 积分**。
> → **不是一个系数换算出来的两个显示，是两套独立数值。**

### 3.5 ⭐⭐ 任务类型 × 奖励触发语义矩阵（九类，全部实证）

| 任务类型 | 触发文案（原文） | 档位 |
|---|---|---|
| 【考勤】 | `考勤完成获取` | 单档 |
| 【活动】 | `活动**合格**获取` | 单档 |
| 【投票】 | `投票完成后获取` | 单档 |
| 【文档】 | `知识学习完成后获取` | 单档 |
| 【面授】 | `面授课完成获取` | 单档 |
| 【调查】 | `调查完成后获取` | 单档 |
| 【作业】 | `作业**合格**获取` + ⭐ `**精华作业**获取` | **双档** |
| 【考试】 | `考试**通过**获取` + ⭐ `考试**优秀**获取` | **双档** |
| 【鉴定】 | （见 §3.6 扣减规则中出现） | — |

**关键结论**：
1. **触发条件分两类** ——
   - **「完成」类**：考勤 / 投票 / 文档 / 面授 / 调查 → 只要做完就发
   - **「合格/通过」类**：活动 / 作业 / 考试 → **必须达到质量门槛才发**
   这与 DIFF-21（含考试的项目"完成"以通过为准）的用户决策**方向一致**，且原站把这个区分做到了**任务类型的默认语义层**，不是每个任务单独勾选。
2. ⭐ **作业和考试有"优秀/精华"第二档**——超额表现额外加码。这是一个**纯激励型的正向设计**，成本低、效果好。

### 3.6 ⭐ 扣减规则：4 条**系统预置**规则

| 规则名称 | 说明（原文） | 可配 |
|---|---|---|
| 学习项目未按时完成 | 员工参与项目，未在项目计划完成时间内完成（**次日凌晨 2 点开始自动更新**） | 扣减学分 / 扣减积分 |
| 考试未通过 | 员工参与的考试，在任务计划完成时间到期后未通过 | 同上 |
| 作业未合格 | 员工参与的作业，在任务计划完成时间到期后未合格 | 同上 |
| **鉴定未合格** | 员工参与的**鉴定**，在任务计划完成时间到期后未合格 | 同上 |

**关键结论**：
1. **规则名称与触发条件是系统固定的，管理员只能配扣减额度**（含配 0 = 不扣）。这是一个**克制的设计**——不给自定义规则引擎，避免复杂度爆炸。**建议复刻这种克制。**
2. ⭐ **「次日凌晨 2 点开始自动更新」——新增一层数据时效！**
   本项目此前记录的时效分层需补充为**五层**：
   | 层 | 频率 |
   |---|---|
   | 数据大屏 | T-1 |
   | 任务进度 | **每 10 分钟**（本次在任务大纲页再次双证：原文「任务进度每10分钟自动更新」） |
   | 进度上报 | ~20 秒节流 |
   | 奖励发放 | 即时 |
   | ⭐ **逾期扣减结算** | **次日 02:00 批处理** |
3. 扣减全部挂在**"计划完成时间到期"**这一个时间锚点上，逻辑统一。

## 4. ⭐ 任务的时间语义【已验证】

- **任务有独立于项目的起止时间**，且**可以为空**（文档类全部显示 `-- 至 --`）。
- **考勤类的时间文案不同**：任务大纲页显示 `2021-03-07 10:00 开始考勤`（单点），而学分页显示区间 `2021-03-07 10:00 至 2022-04-07 11:00`。
- 任务时间**可以超出项目时间**，甚至指向过去（样本中有 2021、2022 年的任务）——原站**不强制校验任务时间落在项目时间内**。

## 5. ⭐ 二维码：面授类无【已验证】
33 个任务中，除 4 个【面授】任务外，其余每个任务都带 `二维码` 入口。
→ **面授有自己的签到码体系（E021），不复用任务二维码。**

## 6. ⭐⭐ V-37 结案：**无法在本环境实验验证，原因已查明**

### 6.1 拿到的直接证据
任务大纲页顶部横幅原文：
> **「任务大纲有草稿态未生效，请前往编辑页处理」**

**证明**：任务大纲存在 **草稿态 / 生效态分离** 机制，与课程「暂存/发布」、项目「未发布/发布」、面授「保存/保存并发布」**同构**。
→ 🟢 **原站在所有主要业务对象上都贯彻了"编辑与生效分离"**，这是一条可以自信复刻的架构级规则。

### 6.2 为什么实验做不成（如实记录，不粉饰）
| 障碍 | 实证 |
|---|---|
| ① 演示租户**没有任何已发布项目** | 项目列表 8 条，**状态全部为「未发布」** |
| ② **没有任何学员有进度** | 33 个任务**全部显示 `0/152人  0%`** |
| ③ 自建项目失败 | `完成创建` 提交后列表无新增；日期控件**滚出视口即重置**，3 次尝试均未过校验 |

→ **既没有"历史数据"，也造不出"历史数据"，因此"规则变更对历史数据的影响"在本试用环境内无法观察。**

### 6.3 结论
- **V-37 转为永久缺口 G-05**，不得标记为已验证。
- **但缺口是"实验条件缺失"，不是"没查"**：机制存在性已证实（§6.1），缺的是**重算语义**（已完成状态是否回退 / 完成度分母是否重算 / 已发学分是否追回）。
- → 这三个语义**必须在目标系统中显式决策**，见 §6.4。

### 6.4 目标系统必须回答的三问（转为待决策 DIFF-33）
| # | 问题 | 建议默认值 | 理由 |
|---|---|---|---|
| a | 大纲新增必修任务后，已"完成"的学员是否回退为"学习中"？ | **回退** | 完成口径是"全部必修完成"，新增必修后原判定已失真 |
| b | 完成度分母是否立即重算？ | **立即重算** | 否则新老学员的百分比不可比 |
| c | 已发放的学分/积分是否追回？ | **不追回** | 已发即既得，追回会引发强烈负面体感；且与 §3.6 的"扣减"是两回事 |

> ⚠️ 以上是**基于原站已验证规则推导的建议**，**不是原站实测行为**。目标系统实现时需作为独立决策确认。
