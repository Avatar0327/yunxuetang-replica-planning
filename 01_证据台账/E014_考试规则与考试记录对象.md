## 3. ⭐⭐ 及格线与成绩规则【已验证】——直接回答规划要求

### 3.1 通过分数（及格线）
页面显示 `当前试卷分数：7分`，通过分数支持**两种设定方式**：
- **固定分数**（填「分」）
- **总分比例**（填「%」）

**【已验证】实测默认值 = 4.2 分（试卷总分 7 分）→ 默认及格线为总分的 60%。**

### 3.2 优秀分数（独立于及格线）
同样支持 **固定分数 / 总分比例** 两种方式。
**【已验证】** 原站有**两条分数线**：及格线 + 优秀线，是不同字段。
→ 规划含义：成绩判定不是二元的（通过/不通过），而是**三档（不通过 / 通过 / 优秀）**。目标产品若只做及格线，属有意简化。列入 **DIFF-20**。

### 3.3 是否必修
考试本身有 **`必修` / `选修`** 属性 → 呼应 E012：必修性是任务级一等属性，考试作为任务同样具备。

### 3.4 学员奖励（与成绩挂钩）
触发时机二选一：**`考试归档后`** / **`考试通过后`**
奖励内容：`获得 N 学分` / `获得 N 积分` / `获得证书`

**【已验证】** 奖励发放时机可选「归档后」或「通过后」——两者语义不同（归档后即使未通过也可能发放）。
→ 这是「完成/通过/奖励」三者解耦的又一例证。**V-41**：归档后发放是否对未通过者也发放，需确认。

## 12. ⭐ 「允许重复考试次数」的完整结构【已验证】

证据位置：考试编辑页 `/ote/#/quickexam/publish/exam?examId=…&arrangeId=…` → 展开更多设置 → 考试设置
操作对象：本次创建的测试考试 `ZZ_YXT20260921A_测试考试`（未发布）

### 控件结构
```
允许重复考试次数（开关，默认关）
 ├─ ○ 不限次
 ├─ ● 限制次数  ⓘ「考生可参与的考试次数」
 │     └─ 次数输入框（默认值 2）
 └─ □ 考试通过后不允许再次考试（开关）
```

### ⭐ V-43 的结论【已验证 + 受限推断】

**【已验证】原站在考试配置中不提供"多次作答成绩取值规则"的配置项。**
展开全部「更多设置」后确认：考试设置区仅有上述次数控制，**没有"取最高分 / 取最近一次 / 取首次"之类的选项**。
→ 即**成绩取值规则是硬编码的，不可配置**。

**【受限推断，非结论】实际取值规则倾向于"取最近一次"**，理由：
1. 考生记录中 `成绩` 是**单值字段**（非作答列表），且有 `排名` 字段 → 每人只保留一个有效成绩。
2. 存在 **「考试通过后不允许再次考试」** 这一独立开关。
   若取值规则是"取最高分"，重考不可能拉低成绩，该开关的保护意义很弱；
   该开关的存在，反向说明**重考可能改变（甚至拉低）已记录的成绩** → 指向"取最近一次"。
3. 首考与补考分列为两组字段（§5），说明平台对"需要并存的成绩"是用**独立字段**解决的，而非版本列表。

⚠️ **上述第 2、3 点是推理，不是实测。** 要定论需以学员身份实际作答两次，本次因无低权限账号（缺口 G-01/G-02）无法执行。
→ **V-43 状态：配置层已结案（无该配置项）；运行时取值规则仍为「未验证」。**
→ **对批次 7 的要求**：目标产品**必须显式定义并文档化**多次作答的成绩取值规则（建议"取最高分"并提供配置项），不得沿用原站的隐式行为。列入 **DIFF-30**。
