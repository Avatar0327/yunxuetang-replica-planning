## 3. 角色 Role 与权限【已验证，E006】

### 角色对象

| 角色人数 | 计数 | |

| 角色描述 | 文本 | |

原站实测 **22 个角色**，V1 只做 3 个：**管理员 / 主管 / 学员**。

### ⭐ 权限模型：三维 + 两来源
**维度一（原站自带三维）**：
```
角色 × 功能节点 → { 导航可见性, 操作权限集, 数据范围 }
```
- **导航**：能否看见该菜单（单个布尔）
- **操作权限**：页面内可执行的操作（多值；部分带「详细权限」二级展开）
- **数据范围**：**按节点单独配置**，不是角色级一刀切【已验证，关键】

**维度二（对象级任命，E010 §8 补充）**：
权限还来自**在业务对象上的任命**：项目负责人、跟踪人、带教导师、团队负责人、课程主讲/辅讲、分类创建者。
→ **目标产品的权限判定 = 角色权限 ∪ 对象级任命**，缺一不可。

### ⭐ 字段级敏感数据权限【已验证】
`身份证号` / `邮箱` / `手机` 在**每个含个人维度的报表节点上都是独立的操作权限勾选项**。
→ **能看报表 ≠ 能看身份证号**。V1 即使不实现，数据模型需预留字段级权限位。

### 学员权限基线【已验证，实测】
**普通学员在管理端 441 个权限项中勾选 0 项** → 学员端与管理端彻底分离，学员无任何管理入口。

### ⭐⭐ 三个正交属性（本次调研最重要的规则，E008 §4.4 原文）
> 「勾选后，所选类型的任务不参与闯关解锁：既不作为解锁下一关的前置，自身也不被前面关卡锁住，学员可随时学习。**不影响该任务是否必修及是否计入项目完成度**。默认不勾选（全部参与闯关）。」

| 概念 | 含义 | 是否互相影响 |
|---|---|---|
| **闯关解锁** | 任务能否被访问（顺序约束） | **独立** |
| **是否必修** | 任务是否必须完成 | **独立** |
| **是否计入完成度** | 任务是否参与完成率计算 | **独立** |

→ **严禁**在目标产品中把三者耦合成单一「必修/选修」开关。

### ⭐⭐ 第四个正交属性：奖励触发语义由**任务类型**决定【已验证，E023 §3.5】

原站把"发奖条件"做在**类型**这一层，管理员选了类型就自动获得正确语义，**不需要每个任务单独勾选**。

| 触发类别 | 任务类型 | 原文 | 档位 |
|---|---|---|---|
| **「完成」即触发** | 考勤 | `考勤完成获取` | 单档 |
| | 投票 | `投票完成后获取` | 单档 |
| | 文档 | `知识学习完成后获取` | 单档 |
| | 面授 | `面授课完成获取` | 单档 |
| | 调查 | `调查完成后获取` | 单档 |
| **须达「合格/通过」** | 活动 | `活动合格获取` | 单档 |
| | 作业 | `作业合格获取` + **`精华作业获取`** | ⭐ **双档** |
| | 考试 | `考试通过获取` + **`考试优秀获取`** | ⭐ **双档** |
| | 鉴定 | （仅见于扣减规则「鉴定未合格」） | 未验证 V-61 |

- ⭐ **这个设计值得复刻**：它把"完成 vs 合格"的区分提升为**类型级默认语义**，与用户 DIFF-21 的决策同向且更彻底。
- ⭐ **双档奖励**（优秀/精华额外加码）是纯正向激励，成本低。**数据结构 V1 就要建全**，即使 V1 只用基础档。

### 任务的时间语义【已验证，E023 §4】
- 任务起止时间**独立于项目**，且**允许为空**（文档类实测全部 `-- 至 --`）。
- ⭐ **原站不校验任务时间是否落在项目时间内**（实测 2021/2022 年的任务挂在 365 天周期项目下）。
- **二维码**：33 个任务中除 **4 个【面授】任务外全部带二维码** → 面授有独立签到码体系（E021），不复用任务二维码。

## 6b. 🆕 奖励规则 RewardRule / 扣减规则 DeductionRule【已验证，E023 §3】

### 发放层次（五级）
| 层级 | 挂载对象 | 原文 | V1 |
|---|---|---|---|
| 任务级 | Task | 见上表 | ✅ |
| 阶段级 | Stage | `选修和必修 完成后，获取 X 学分` | ✅ |
| 项目级 | Project | `完成所有选修和必修后，获取 X 学分` | ✅ |
| 评优级 | Project×优秀学员 | `优秀学员可获取 X 学分 Y 积分` | ⛔ 预留事件 |
| 带教级 | 带教评价 | `学员每次获得的评价为合格/不合格时…` | ⛔ 预留事件 |

### ⭐ 币种是集合，不是两列
- 实测 `基础知识考试` = **20 学分 / 30 积分**，`结业考试` = **30 学分 / 15 积分** → **两个独立字段，非系数换算。**
- **数据模型要求**：奖励值存为 `{currency, amount}` **集合**，V1 只填 `credit` 一种。V2 加积分是**加数据**不是**改表**。

### ⭐ 奖励上限预计算
原站原文：「**当前设置下，本项目学员有机会获取 340 学分 355 积分**」——实时汇总全项目奖励天花板。
→ **防学分通胀的唯一低成本手段**，建议复刻。

### 扣减规则：系统预置 4 条，只配额度
| 规则 | 触发条件（原文） |
|---|---|
| 学习项目未按时完成 | 员工参与项目，未在项目计划完成时间内完成 |
| 考试未通过 | 员工参与的考试，在任务计划完成时间到期后未通过 |
| 作业未合格 | 员工参与的作业，在任务计划完成时间到期后未合格 |
| 鉴定未合格 | 员工参与的鉴定，在任务计划完成时间到期后未合格 |

- **规则名与触发条件不可自定义**，管理员只能配数值（配 0 = 不扣）。⭐ **这种克制值得复刻**——不做自定义规则引擎。
- 全部锚定在**「计划完成时间到期」**这一个时间点，逻辑统一。

## 12. ⭐ 人次 vs 人数（必须逐指标标注）【已验证】
| 单位 | 使用场景 |
|---|---|
| **人数** | 平台总览的人员指标（活跃人数、学习人数、启用人数）；课程统计（浏览/学习/完成人数） |
| **人次** | 项目/考试统计（覆盖人次、学习人次、完成人次、参考人次、通过人次）；比率公式的分子分母 |

⚠️ **原站同一概念在不同页面单位不同**（课程管理列表"学习人数" vs 首页看板"学习人次"，DIFF-08）。
→ V1 规定：**每个指标必须显式标注单位，全站同名同义。**

## 13. ⭐ 比率指标的分母不一致【已验证】
| 指标 | 分母 |
|---|---|
| 学习率 / 完成率 | **覆盖人次** |
| 考试通过率 | **考试参考人次**（不是覆盖人次） |

→ **未参加考试的人不拉低通过率，但未学习的人会拉低学习率。**
这是有意设计还是历史遗留**未验证（V-22）**。规划时必须逐指标写明分母，不可统一处理。

### 分母为 0 时的显示（DIFF-01）
原站：比率显示 `0%`。**V1 规定：显示 `--`**（有意差异，避免"无人参考"被误读为"通过率0%"）。

## 14. ⭐⭐ 三态分离的强制规定【已验证，E013 §1 + E015 §7.2】

> 直接回应用户要求的「区分打开页面、播放内容、记录进度、课程完成、项目完成」。

| 态 | 触发条件 | 对应指标 | 界面证据 |
|---|---|---|---|
| ① **打开页面** | 进入课程详情页 | **浏览人数 / 浏览次数** | 页面显示「已完成 0%」，视频**不自动播放** |
| ② **播放内容** | 点击「**开始学习**」 | **学习人数** | 必须显式点击才开始 |
| ③ **记录进度** | 播放过程中节流上报（约20秒） | 进度 % | 66s 显示52%，97s 显示70%（滞后） |
| ④ **课程完成** | **累计观看达视频总时长** | **完成人数** | 状态变「已完成学习」+ 弹完课评论 |
| ⑤ **项目完成** | **全部必修任务完成**（可配置） | 项目完成人次 | 项目头部常驻「项目完成标准」 |

### ⚠️ 必须写入验收的三条反直觉规则
1. **"打开即完成"**（E013 §2 原文）：「若学员已完成某课程，则当其参与的新项目包含相同课程且开启进度同步时，**学员打开课程即完成**，系统自动将其计入该课程的**完成人数**；若学员**没有继续学习的行为发生，将不会计入学习人数**。」
   → **完成人数 与 学习人数 可以不相等，这不是 Bug。**
2. **进度100% 与 学习时长 可以同时是 100% 和 0**（E015 §7.6 实测）。
   → **不能用学习时长推导完成状态，也不能反推。**
3. **学员完成后当日看板无数据**（T-1）。

## 15. 组织范围的三重口径【已验证，E013 §6】
统计按部门时必须同时明确三件事，缺一不可：
1. **按主部门还是含兼职部门** —— 原站：**仅主部门**（「部门人数：当前部门下的人数，不包含兼职人员」）
2. **是否含子部门** —— 原站：**可选**（`统计子部门数据：是/否`）
3. **人员状态过滤** —— 原站：看板硬性仅启用；报表**可选**（启用/禁用/删除，默认启用）

## 16. 空值语义规范（V1 新建，对应 DIFF-03）
原站三种表示混用（`暂无` / `--` / `0`）。**V1 统一规定**：

| 场景 | 展示 | 含义 |
|---|---|---|
| 字段未配置 / 未填写 | `未配置` | 业务上尚未设置 |
| 有统计但无数据 | `--` | 查询成功，结果为空 |
| 有统计且值为零 | `0` / `0%` | 真实的零值 |
| 比率的分母为 0 | `--` | 不可计算 |
