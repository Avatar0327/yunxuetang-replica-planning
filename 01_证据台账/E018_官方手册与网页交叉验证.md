## 1. 🟢 数据权限范围枚举（双证）—— 重大缺口 G-03 的实质性解决

**手册原文**（我的企业·三·3 设置数据权限）：
> 以用户组为例，可设置当前角色组中的人员的相关管辖范围为【全部数据】【本部门及下属部门数据】【本部门数据】【指定部门数据】【管辖范围内的数据】【自己的数据】。

**网页实测**（`/#/role/mgmt` → 角色 → 设置数据权限 → 范围下拉）：
```
全部数据 / 本部门及下属部门数据 / 本部门数据 / 指定部门数据 / 管辖范围内的数据 / 自己的数据
```
**完全一致，6 项。**

### 结论【已验证】
- 数据权限**不是自由配置，而是从 6 个预置范围中选择**。
- **主管的"多级下属"就是「本部门及下属部门数据」** → 此前标记为设计建议的 G-03 现已有原站依据。
- 「管辖范围内的数据」对应手册所述的**人员级管辖范围**（角色人员管理中可逐人设置）。

### 🟢 附加双证：添加授权人员
**手册**：「点击最下方的【添加授权人员】可对当前角色下的部分人员设置独立的数据权限范围」
**网页**：弹窗底部确有「添加授权人员 / 可对当前角色下的人员设置独立的数据权限范围」
→ **数据权限存在三级**：角色级 → 人员级管辖范围 → 单人独立覆盖。

### 🔵 网页补充
不同功能节点的数据权限**维度不同**。实测积分商城节点为：授权角色 / 商品范围 / 人员选择范围 / 自营商品订单查看范围 / 商品分类范围。
→ 印证 E006 §1：数据范围按节点单独配置，**且每个节点的可配维度由该节点业务决定**。

## 2. 📘 角色等级的业务作用（V-15 解答）

**手册原文**（我的企业·三·1 创建角色）：
> 在【新增角色】页面输入角色名称，选择角色等级（**2 级或 3 级**）。需注意，**2 级角色不能修改高等级及同等角色权限，设置权限时仅能在自己权限范围内选择；3 级角色同样不能修改高等级及同等角色权限**。

### 结论【手册记载】
- **新建角色只能选 2 级或 3 级**（1 级为系统预置，不可新建）→ 印证 E006 实测：1 级仅平台管理员与运营负责人。
- **角色级别的作用 = 授权上限约束**：不能修改同级或更高级角色的权限；**设置权限时只能在自己的权限范围内选择**（不能越级授权）。
- → **V-15 解答。** 这是防止权限提权的重要机制，**建议目标产品复刻**。

### 📘 角色人员管理补充
- 添加人员支持**高级选人**及**导入用户**
- **关联用户组最多 10 个**
- 每个人员后方可单独设置**【管辖范围】**

### ⚠️ 菜单路径差异
手册写：【全部应用】—【权限配置】—【角色权限】/【数据权限】
网页实测：【我的企业】下的【角色权限】，且**数据权限不是独立菜单**，而是角色权限页内每个节点的「设置数据权限」入口。
→ **按用户指示以网页为准**：本租户无独立的「权限配置」应用，数据权限内嵌在角色权限页中。
→ 【未验证】是否因本租户未开通「权限配置」独立应用所致 → **V-52**

## 3. 🟢 完课标准（V-27 彻底解答）

**网页实测**（课件详情页 `/kng/#/courseware/info?kngId=...`）：
> **完课标准：完成标准时长的 100% 获得学分**
> 标准时长：**12 分 10 秒**（获得学分所需的学习时长）
> 学分（跟随学时学分策略）：**1.22 学分**

**网页实测**（课件管理 → 批量操作）：下拉菜单中确有 **「设置完课标准」**。

### 结论【已验证】
1. **完课标准是「课件级」属性**，可单个设置也可批量设置。
2. 完课标准的表达式是 **「完成标准时长的 N%」**，实测值 100%。
3. **学分与完课标准绑定**：达到完课标准即获得学分。
4. **学分换算规则再次印证**：12 分 10 秒 = 12.167 分钟 × 0.1 = **1.217 ≈ 1.22 学分** ✓
   → 与 E015 §3 实测（1.9 分钟 → 0.19 学分）**两处独立印证同一规则**。

### 🔵 网页补充字段（E008 的补全）
- **平台课程编号**：`ZXKT2021022500257` —— **系统生成，与用户填写的「编码」是不同字段**
- **下载权限**：不允许下载（独立于浏览权限）
- **App缓存课件权限**：不允许缓存（独立权限项）
- **推荐系数**：0
- **AI字幕**：未开启

### 📘 学分策略的完整规则（手册）
**在线课堂 → 更多管理 → 课程设置 → 学分策略设置**：
- 可按课件类型分别设置：视频/音频、文档、微课、scorm、html
- **应用范围二选一**：`应用于新的文档`（仅后期新上传生效，已上传的不变）/ `应用于所有文档`（全部重算）
- ⭐ **学分发放时间二选一**：`每学完一个课件任务就获得学分` / `学完整个课程后发放所有课件的学分`
- ⭐ **视频课件的学时不支持手动修改**，系统默认取视频本身时长

→ **规划含义**：学分发放时机是配置项，直接影响"学员中途退出是否已拿到部分学分"。**必须写入需求基线。**

## 4. 📘 防挂机机制（V-48 的新线索）

**手册原文**（在线课堂 → 课程设置 → 防挂机设置）：
> 模式一：系统检测到学员疑似挂机后，会弹出是否在线的弹框，让学员确认是否在学习，不在线会停止播放；
> 模式二：系统检测到学员疑似挂机后，会弹出是否在线的弹框，需要学员在 xx 秒内确认在线，**如学员未在规定时间内确认，本次学习无效**。例如：学员有一门课学习到 20 分钟，本次学习时未在规定时间内确定在线，则**再次播放时会回到 20 分钟，并且本次不会获得学时、学分**。
> 同时还有**防多知识同时学习**功能，同一时间只能学习一个知识；
> **禁止拖拽学习**，开启后，针对视频和音频类课件**在首次学习完课时均不可拖拽，当学习完成后，重复学习不限制拖拽**。

### 结论【手册记载】
1. **「本次学习无效」会同时作废学时与学分** → 这是学习时长可能为 0 的一种机制性解释。
   - ⚠️ 但本次实测中 admin **获得了学分 0.19**，说明学习并非"无效"。故**不能解释 V-48**。
   - → V-48 仍为未结案项。
2. **禁止拖拽的精确规则**：**仅首次学习完课前禁止；完成后重复学习不限制拖拽**。
   → 这比 E008 记录的"课程级开关"更精确，**修正 REQ-STU-03**。
3. **防多知识同时学习**：同一时间只能学一个知识。
   → 原站有防并发刷时长机制，**V1 建议纳入**（对应 DIFF-26 的时长可刷风险）。

## 5. 🟢 课件 vs 课程（V-23 彻底解答，且发现真实口径缺陷）

**网页实测**：
| 位置 | 数值 | 实际统计对象 |
|---|---|---|
| 首页看板「**课程总量**」 | **129** | **课件** |
| 分类管理「**课程数**」合计 | **132** | **课件 + 课程包** |
| 课程管理列表 | **3**（含本次新建 2 门） | **课程包** |

**验算**：129 课件 + 3 课程包 = 132 ✓ 完全吻合。

**手册佐证**：课程包「标准时长和学分无需设置，会根据添加的单个内容自动计算总时长和学分」；课件有「引用记录：查询课件被引用到哪些课程及项目中」。

### 结论【已验证】—— 一个真实的口径缺陷
**「课程」一词在原站三处指代三种不同对象**：
- 首页看板的"课程总量" → 实为**课件数**
- 分类的"课程数" → 实为**课件+课程包**
- 课程管理的列表 → 实为**课程包**

→ **列入 DIFF-27（原站缺陷，明确不复刻）**：目标产品必须严格区分**课件（Courseware，单个内容）**与**课程（Course，内容包）**两个对象，并在所有指标上明确标注统计对象。
→ 这也**推翻了我此前"admin 可管理范围受限"的推测（V-50）**：admin 能看到全部 129 个课件，并非数据范围受限。

# 附录：2026-09-21 平台侧故障期间的观察（意外取得的高价值证据）

## 现象【已验证】
调研后段（本地时间约 02:50 起）平台出现服务端故障：
- 控制台错误：`502`、`net::ERR_CONNECTION_RESET`、多个 `404`
- `/study/#/userhome` 学员端**页面骨架渲染但正文为空**（body 仅 197 字符）
- 门户首页**可渲染，但所有指标归零**：启用人数 `156 → 0`、课程总量 `129 → 0`、应用宫格为空
- 约 20 分钟后**部分恢复**：启用人数回到 `156`，但课程总量仍为 `0`

## ⭐ 由此暴露的真实缺陷【已验证】—— DIFF-29

> **取数接口失败时，数据看板降级展示为 `0`，而不是错误提示或 `--`。**

### 为什么这是严重缺陷
管理员**无法区分以下两种完全不同的情况**：
| 情况 | 业务含义 | 应采取的行动 |
|---|---|---|
| 真实值为 0 | 本期确实无人学习 | 推动学习、催办 |
| **取数失败** | 系统故障 | 报修、**不要据此做业务判断** |

两者在界面上**显示完全相同**（都是 `0`）。管理员可能据此做出完全错误的运营决策（例如误判"本月无人学习"而发起大规模催办）。

### 与既有差异项的关系
这与 DIFF-01（分母为 0 显示 `0%`）、DIFF-03（三种空值表示混用）是**同一个系统性问题**：
**原站缺乏统一的"无数据 / 零值 / 异常"三态语义。**

### 规划要求（列入需求基线）
目标产品的数据展示必须区分**四种状态**，且**视觉上可辨**：

| 状态 | 展示 | 说明 |
|---|---|---|
| 正常有值 | 数值 | |
| 真实零值 | `0` | 查询成功，结果为 0 |
| 无数据/不适用 | `--` | 查询成功但无记录，或分母为 0 |
| **取数失败** | **明确的错误态 + 重试入口** | **绝不可降级为 `0`** |

**验收场景 AC-E-14🆕**：模拟统计接口返回 5xx → 预期看板显示明确错误提示与重试按钮，**不显示任何数字**。
