## 4. 数据范围矩阵

| 角色 | 组织范围 | 数据范围来源 | 证据 |
|---|---|---|---|
| **管理员** | 全租户 | 角色配置 | E006 |
| **主管** | **直属经理 = 本人** 的人员 | **人员档案的「直属经理」字段**，不从组织树推导 | **E005 §3 + E010 §6【已验证】**（原站实测：项目学习进度自动发送给学员的「直属经理」） |
| **学员** | 仅本人 | — | E006 §4.1 |

### 【已验证】数据范围是按节点单独配置的
原站在**几乎每个功能节点上都有独立的「设置数据权限」入口**（E006 §1）。
→ 同一角色在"课程管理"与"学习报表"上可以有不同的数据范围。
→ **V1 必须实现为 `角色 × 节点 → 数据范围` 的三元组，不能做成角色级单一范围。**

### 🟢 v2.0 升级：数据范围是 6 个预置枚举（手册 + 网页双证）

**手册原文**（我的企业·三·3）与**网页下拉实测**完全一致：

| 范围 | 含义 | 适用角色 |
|---|---|---|
| **全部数据** | 全租户 | 管理员 |
| **本部门及下属部门数据** | 本部门 + 所有子部门 | **主管（V1 采用此项）** |
| **本部门数据** | 仅本部门，不含子部门 | 部门内协助员 |
| **指定部门数据** | 手工指定若干部门 | 区域/事业部管理员 |
| **管辖范围内的数据** | 按人员级「管辖范围」设定 | 分级管理员 |
| **自己的数据** | 仅本人 | 学员 |

**→ G-03 的核心问题已解决**：主管"多级下属"不是我的推测，而是原站预置的 **「本部门及下属部门数据」**。
**→ v1.0 中"含多级下属"的设计建议，现已有原站依据支撑，标记从 🔴 升级为 🟢。**

### 🟢 数据权限的三级覆盖（双证）
1. **角色级**：为角色在某功能节点上设定范围
2. **人员级**：角色人员管理中，为每个人单独设置「管辖范围」
3. **单人覆盖**：「添加授权人员」可对角色下**部分人员设置独立的数据权限范围**

### 🔵 网页补充
不同功能节点的数据权限**可配维度不同**（实测积分商城节点为：商品范围/人员选择范围/商品分类范围），由该节点业务决定。

### 🟡 仍受限的部分
- 主管账号的**实际行为**未实测（无主管账号）。
- 📘 手册另提到自动督学可发给「**部门主管或者直属经理**」→ 主管可能有**两种来源**（组织树 vs 人员字段）。**V-53 待验证**，V1 建议两者皆支持。

## 5. 权限拒绝场景

### 5.1 唯一的原站实测证据【已验证 E008 §2】
访问 `/kng/#/overview/resource` 时，**admin 自己**被拒绝，页面显示：
> **「暂无权限查看课堂数据，请联系管理员开通权限　开通路径：管理端–在线课堂–企课堂–编辑企课堂」**

**由此可确认的原站拒绝 UX 模式**：
1. **不使用 403 错误页**，在页面内展示友好空状态
2. **给出具体的开通路径指引**（精确到菜单层级）
3. **即使是 admin 也存在无权限的模块** → 再次佐证 V-16：平台管理员并非全权

### 5.2 V1 必须覆盖的拒绝场景（🔴 原站均未实测，为设计要求）
| # | 场景 | 预期表现 |
|---|---|---|
| D-1 | 学员直接访问管理端 URL | 页面内友好提示 + 引导回学员端，不暴露技术错误码 |
| D-2 | 主管访问非下属的个人学习详情 | 查询结果为空 + 提示"超出你的数据范围" |
| D-3 | 主管访问管理员专属的课程编辑页 | 拒绝 + 指明所需权限 |
| D-4 | 仅有"浏览"权限者尝试编辑课程 | 编辑入口不可见，直接调接口被拒 |
| D-5 | 仅有"维护"权限者尝试把课程加入项目 | 分发入口不可见，直接调接口被拒 |
| D-6 | 学员访问他人的学习记录 | 拒绝 |

> **纪律**：D-1~D-6 的预期表现是**我们的设计要求**，不是"原站这样做"。交付时须如此表述。

## 6. 🆕 角色等级的授权上限约束（V-15 已解答）

📘 **手册原文**：
> 新增角色时「选择角色等级（**2 级或 3 级**）。需注意，**2 级角色不能修改高等级及同等角色权限，设置权限时仅能在自己权限范围内选择**；3 级角色同样不能修改高等级及同等角色权限」

**→ V-15 解答**：角色等级的作用是 **授权上限约束**：
1. 新建角色只能选 2/3 级（1 级系统预置不可新建）—— 🔵 网页佐证：实测 1 级仅 2 个角色
2. 不能修改**同级或更高级**角色的权限
3. 授权时**只能在自己已有的权限范围内选择**（不能授予自己没有的权限）

**建议目标产品复刻**：这是防止管理员越级提权的关键机制。对应 REQ-ROLE-06、AC-P-07。
