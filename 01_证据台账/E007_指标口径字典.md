## 1. ⭐ 数据时效性【已验证】——直接回答「报表统计时间」

> **原文：数据大屏统计逻辑为T-1，即每天统计截止前一天24点的产生的数据，非实时数据。**

**【已验证】结论**：
- 统计口径为 **T-1**，切点是**前一天 24:00**
- **非实时**
- → 学员今天完成的学习，**今天在大屏上看不到**，次日才体现。

**规划含义（重要）**：
- 这是一条必须显式写入需求基线的规则。若目标产品做成实时统计，是**有意差异**，须评估性能代价。
- 验收场景必须包含：「学员完成学习后，管理员当日查看统计 → 预期数据未更新」这一**反直觉但正确**的场景，否则会被误判为 Bug。
- 列入 **DIFF-05（待用户决策：T-1 还是实时）**
- 【未验证】T-1 仅适用于「数据大屏」，还是同样适用于「报表中心」的明细报表？两者可能不同源。→ **V-18（高优先）**

## 2. ⭐ 统计人群范围【已验证】——直接回答「人员停用后的记录保留」

> **原文：仅统计启用人员，不统计禁用、删除人员和游客的数据**
> （该说明同时出现在「活跃人数」与「活跃时长」两个指标上）

**【已验证】结论**：
- 统计**仅含启用状态人员**
- **禁用人员、已删除人员、游客** 三类均**被排除在统计之外**
- → **人员一旦禁用，其历史学习数据即从统计口径中消失**（数据本身可能仍保留，但不参与统计）

**规划含义（重要且高风险）**：
- 这会导致**历史报表不可复现**：上月统计时某人是启用的，本月被禁用后再查上月数据，结果会变小。
- 这是典型的**原站缺陷候选**，不应直接转为目标产品要求。
- **建议目标产品**：统计时区分「按当前人员状态过滤」与「按统计时点的人员状态快照」，默认采用后者以保证历史可复现。
- 列入 **DIFF-06（建议有意差异，待用户决策）**
- 【未验证】「删除人员」是否为软删除（E005 已发现「恢复账号」功能 → 确为软删除），恢复后统计是否回补。→ **V-19**

## 3. ⭐ 学习时长的来源二分【已验证】——直接回答「指派 vs 自主」

> **原文1：指派学习时长为在项目、人才发展模块学习课程获得的时长**
> **原文2：自主学习时长为在在线课堂学习课程获得的时长**

**【已验证】结论**：
学习时长按**学习发生的入口模块**二分，而非按「是否被指派」的任务属性：

| 类型 | 判定依据 | 来源模块 |
|---|---|---|
| **指派学习时长** | 在**项目**、**人才发展**模块中学习课程 | `/o2o/` 培训中心等 |
| **自主学习时长** | 在**在线课堂**中学习课程 | `/kng/` 在线课堂 |

**规划含义（关键）**：
- 学习记录对象**必须携带「学习入口/来源」字段**，且该字段决定时长归类。
- **同一门课程**通过不同入口学习，会被归入不同的时长类别。
- 这也意味着：目标产品若把「课程学习」做成单一入口，将**无法还原这一区分**——需在 V1 就决定是否保留双入口。列入 **DIFF-07（待用户决策）**。
- 【未验证】同一课程既被指派又被自主学习时，进度与完成记录是**合并**还是**分别记录**？这是 P0-3 c/e 段必须实测的核心问题。→ **V-20（最高优先）**

## 4. ⭐ 学习时长的计入规则【已验证】

> **原文：仅统计时长规则中配置了计入时长的模块产生的时长数据**

**【已验证】结论**：
- 平台存在**「时长规则」配置项**（E006 权限树中已见 `时长规则 → 时长设置 → 时长规则设置`）
- **哪些模块的行为计入学习时长是可配置的**，不是固定规则
- → 「学习时长」不是一个固定口径，而是**租户可配置的口径**

**规划含义**：目标产品需明确：学习时长口径是固化还是可配置。V1 建议**固化并显式写明计入范围**，避免可配置带来的口径歧义。列入需求基线。
- 【未验证】默认哪些模块计入、哪些不计入。→ **V-21**

## 5. ⭐ 核心比率公式【已验证】

> **原文：1、学习率=学习人次/覆盖人次**
> **原文：2、完成率=完成人次/覆盖人次**
> **原文：1、通过率=考试通过人次/考试参考人次**

| 指标 | 公式 | 分母 |
|---|---|---|
| 学习率 | 学习人次 ÷ **覆盖人次** | 覆盖人次 |
| 完成率 | 完成人次 ÷ **覆盖人次** | 覆盖人次 |
| 考试通过率 | 考试通过人次 ÷ **考试参考人次** | 参考人次（**不是覆盖人次**） |

**【已验证】关键差异**：
- 学习率/完成率的分母是「**覆盖人次**」（被指派/被覆盖的总人次）
- 通过率的分母是「**参考人次**」（实际参加考试的人次）
- → **未参加考试的人不拉低通过率**，但未学习的人会拉低学习率。两者分母口径**不一致**，这是有意设计还是历史遗留需确认。
- 列为 **V-22**；规划时必须逐指标写明分母，不可统一处理。

**【已验证】人次 vs 人数**：
- 原站在课程/项目/考试统计中使用「**人次**」（学习人次、完成人次、覆盖人次、参考人次）
- 在平台总览的人员指标中使用「**人数**」（活跃人数、学习人数、启用人数）
- → 两套计数单位并存，**目标产品必须在每个指标上显式标注单位**，否则必然出现口径误读。

## 6. 已确认的指标定义汇总【已验证】

| 指标 | 官方定义原文 | 单位 |
|---|---|---|
| 活跃人数 | 当前统计周期内产生了活跃时长的人数 | 人数 |
| 学习人数 | 当前统计周期内产生了学习时长的人数 | 人数 |
| 启用人数 | （未给出说明，实测值 156，为租户启用状态人员数） | 人数 |
| 活跃时长 | 当前统计周期内产生的活跃时长之和 | 小时 |
| 学习时长 | 当前统计周期内产生的学习时长之和 | 小时 |
| 总学分 | 当前统计周期内，获得的学分 | 学分 |
| 指派学习时长 | 在项目、人才发展模块学习课程获得的时长 | 小时 |
| 自主学习时长 | 在在线课堂学习课程获得的时长 | 小时 |
| 学习率 | 学习人次/覆盖人次 | % |
| 完成率 | 完成人次/覆盖人次 | % |
| 考试通过率 | 考试通过人次/考试参考人次 | % |

**【已验证】「活跃」与「学习」是两个独立度量**：活跃时长 ≠ 学习时长，活跃人数 ≠ 学习人数。
登录/浏览产生活跃，只有「时长规则中配置计入」的模块行为才产生学习。
→ 这是对规划要求中「打开页面 / 播放内容 / 记录进度」三态区分的**上游制度性证据**。
