## Findings

### I1 — Important：任命 ID 拼接碰撞可修改未被本次授权的另一条关系

- 位置：`src/training/service.ts:55–63`，核心 `:61–62`；`sql/schema.sql:15`。
- 证据等级：静态发现，本审查未执行定向复现。
- `appoint` 对请求中的 project/person 做授权后，以 `${personId}-${projectId}` 为行 ID，按 `(tenant_id,id)` 冲突只更新 `active`。内核规定 ID 为 opaque string，未禁止连字符。`personId=A-B, projectId=C` 与 `personId=A, projectId=B-C` 均得到 `A-B-C`。
- 如果前一关系已存在，第二个请求即使仅获第二个项目/人员授权，冲突分支也会切换第一关系的 active；不会检查或重绑已存的 person/project。结果可以撤销或恢复另一项目/人员/公司的任命并返回成功，越过本次真实目标校验。两个候选共享此路径。
- 建议：使用无碰撞行 ID，并建立 `(tenant_id,person_id,project_id)` 语义唯一约束，按准确已授权关系处理幂等冲突。不要只换一种可能冲突的分隔符。修复前由控制器复现；两候选回归应覆盖上述两对 ID、激活/撤销、无关关系不变以及同一关系重复操作幂等。

### I2 — Important：JS/数据库排序差异误拒合法批次，并影响部门移动

- 位置：`src/training/enrollment-service.ts:19–31`；`src/organization/service.ts:58–61`。
- 证据等级：报名 add 已有实际 RED，其他列出路径为静态同型分析。
- 请求 ID 用 JS `.sort()` 排序；授权 SQL 用 PostgreSQL `ORDER BY id/person_id` 排序，之后以 JSON 数组严格相等判断全员授权。当前 PostgreSQL `en_US.utf8` 与 JS 对混合大小写 ID 的顺序不同。
- 已保存合法请求 `POST /projects/P/enrollments`、`{"operation":"add","personIds":["Y","person-00002"]}`：两人均为当前 B 公司有效人员，Y 为合法任命人；JS 顺序为 `["Y","person-00002"]`，数据库顺序为 `["person-00002","Y"]`。Native 和 Casbin 均期望 200、实际 403。
- 原始记录：`evidence/raw/task5-fix-round1-out-of-scope-sort.json` 保存 SQL 人员/顺序与请求；`evidence/raw/task5-fix-round1-red.jsonl` 中两候选的 `R1 same-company add response 0` 保存 expected 200 / actual 403；`task-5-fix-round1-report.md` 明确保留该问题。正向夹具改用 W 没有修复排序。
- 同型逻辑还用于直接团队报名、remove 的 roster 全员校验，以及部门移动的子树加目标父部门 ID 集合，可能误拒合法操作。没有证明它会放行未授权成员，影响为合法功能失败及未满足验收。
- 建议：以与数据库 collation 无关的集合相等检查代替数组顺序比较，保留重复请求拒绝、全目标存在/授权、事务原子性。补两候选项目/直属团队 add/remove、混合大小写部门子树/父节点正例，以及一名越权时整批不变反例；不得改 ID/夹具/数据库排序掩盖问题。

### I3 — Important：分类修改接口通过 403/503 暴露目标是否存在

- 位置：`src/knowledge/public.ts:12–15`；`src/knowledge/service.ts:55–58`（调用路径 `:70–85` 及 recheck）；`src/bootstrap.ts:46–48`。
- 证据等级：静态发现，本审查未执行定向 HTTP 复现。
- `configure` 在判断权限前加载当前租户分类并调用 `effectiveCategory`。有效但无权限的分类最终抛 Denied；不存在或仅另一租户存在的 ID 使 `effectiveCategory` 抛普通 Error（missing category ancestor）。HTTP 包装把普通 Error 映射成 Unavailable 503，而 Denied 为 403。
- 因此无分类权限的已认证身份可用相同合法请求体比较不可访问的存在 ID 与不存在 ID，区分状态和业务消息。分类更新、导入、追加/预览及 recheck 共享该路径，违反批准设计 §6.4 / AUTH-T10 的等价安全拒绝。已有报表拒绝三元组证据不能替代这些分类路径。
- 建议：所属领域边界明确将当前租户缺失目标映射为统一 Denied，保留真实祖先损坏/基础设施异常为服务不可用；检查创建的缺失父节点等关联路径。对不可访问/不存在/外租户分类验证状态与安全业务响应一致（不要求动态时间/诊断 meta 字面相同），同时保留授权正例、批次失败无写入及真实故障 503 证据。

### I4 — Important：in-DOM 自闭合组件破坏模板，真实浏览器页面空白

- 位置：`web/index.html:9`，同类标签另见 `:4,6,8,11`；in-DOM 挂载见 `:23`。
- 证据等级：控制器实际 Chrome 首轮 RED，本审查读取原始文本并结合源码分析；截图目视结论由控制器提供，本审查没有自行启动浏览器或查看截图。
- 在冻结版本的受限容器 B（`http://127.0.0.1:4312`）打开页面后，快照为空，控制台报 Vue production `compiler-30` SyntaxError。`<el-empty v-if="!projects.length" .../>` 紧接 `<el-table v-else ...>` 写在浏览器解析的 HTML 内；浏览器不会把自定义元素的 `/>` 视为闭合，后者会成为前者子节点而非合法相邻 v-else，符合该编译失败。其他自闭合组件也有解析风险。
- 原始记录：`output/playwright/native-01-open.txt`、`native-02-learner.txt`、`native-console-initial.txt`；控制器另保存并目视确认 `native-initial.png` 全空白。favicon 404 与主故障无关，不将其单独列为阻断。
- 最小壳无法渲染，学员入口、后台导航、项目直达、拒绝提示、撤权后返回学员端都无法完成真实浏览器验证。
- 建议：将所有 in-DOM 自定义组件写成显式闭合标签，或采用正确的编译/字符串模板方式。修复后控制器对两候选执行完整要求的真实浏览器状态转换并保存快照/控制台；仅 HTTP/source 测试通过不能关闭此项。
