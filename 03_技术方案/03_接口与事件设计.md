# 接口与事件设计

版本：v1.0 设计定稿｜更新：2026-09-23｜适用范围：路径 A｜状态：技术设计，未实现、未联调、未压测。

本文给出 Vue 3 + TypeScript + Element Plus 前端与 NestJS（Fastify）模块化单体之间的契约。持久化使用 PostgreSQL，Redis 用于会话缓存、限流、短租约与调度加速；文件使用对象存储与 CDN。Redis 不作为学分、学习上报成功或大纲生效的最终事实来源。

优先采用本轮已确认口径：课程默认每完成任务发放学分；追回不产生负余额、不足记待抵扣；团队管理按 `直属经理 = 当前用户`；报表权限按功能节点的六种范围独立求值。D-42与T-10均是我方定义，分别对应永久缺口G-05/G-06，原站相应行为未验证。历史文档中已撤销的微前端、课程审核和下架后可继续学习文字不再构成接口要求。业务冲突已按T-01～19与终审确认定案，第12节保留映射；工程配置和运行验证另行记录，不改写原站证据。

## 1. 边界与公共契约

### 1.1 模块责任

| 模块 | 本期接口责任 | 拥有的权威事实 |
|---|---|---|
| `organization` | 部门、人员、岗位、角色/授权配置的管理界面与路由、标签治理 | 人员当前资料与状态、组织关系；授权配置路由委托 authz，不直接持有授权表 |
| `knowledge` | 分类、课件、课程草稿/发布、内容访问 | 内容及其版本、可见范围、媒体可用状态 |
| `training` | 项目、阶段/分组/任务、指派、项目记录、大纲变更 | 项目和大纲版本、项目成员、项目完成/毕业规则 |
| `study` | 浏览、来源记录、学习会话、上报、课程完成、反馈 | 服务端接收的学习证据、课程/课件进度与完成事实 |
| `offline` | 面授、场次、考勤、请假、成绩、固定评价、时长核实 | 线下面授事实与完成结果 |
| `operations` | 奖励配置、学分账本、待抵扣、扣减结算；持有时长动作策略并由study应用 | 奖励权益与不可变账务流水 |
| `report` | 三张最小报表、汇总数据、导出与领取 | 自有报表投影、导出快照与任务状态 |
| `identity` | 登录身份、凭证、会话和解锁 | `login_identity/login_session`；与人员当前有效状态协同校验 |
| `authz` | 统一 `AuthzService` 外观、唯一 `PolicyService`、动作和范围求值 | 角色/授权权威配置、权限版本、同步任命索引；对象任命事实仍属对应业务模块 |
| `files` | 上传签名、文件处理、播放/下载交付 | `asset/asset_revision`、处理结果、受控访问票据；调用 authz 与内容拥有方校验访问 |
| `messaging` | 站内消息、未读数、已读状态 | 用户消息与投递状态 |

模块间调用 `OrganizationPublic`、`KnowledgePublic`、`TrainingPublic`、`StudyPublic`、`OfflinePublic`、`OperationsPublic`、`ReportPublic`、`MessagingPublic`、`FilesPublic`、`IdentityPublic`；同进程调用，无需为了模块化单体增加内部 HTTP。只能访问自己模块的仓储，不能通过 SQL、ORM 关系或数据库视图绕过边界读取其他模块的业务表。需要同一事务的调用由应用层传递 `UnitOfWork`，各服务仍只操作自己拥有的数据。`AuthzService` 只是公共外观，内部唯一委托 `PolicyService`，不得维护第二套判定规则。

考试、练习、调查引擎、培训规划、通用审核中心、游客、第三方组织同步、飞书/钉钉均没有本期业务接口。面授请假只做单级固定审批，双向评价只做固定表单。活动、作业、考勤按 REQ-INC-03/05 提供最小任务结果支持，不扩展成完整测练平台；表单按T-17固定；开发工作量需结合实际预研重估，不能将表单设计视为功能已实现。

### 1.2 HTTP、类型与时钟

- 外部前缀为 `/api/v1`，使用 HTTPS、REST + JSON；接口表中的路径均省略此前缀。路由 ID 使用 UUID 字符串；不接受客户端提供的 `tenantId`、实际发分数值、实际完成人或实际审批人。
- 所有请求由会话确定租户和操作者。租户 ID 仍写入数据、唯一约束、审计与事件；跨租户对象与不存在对象统一返回业务化的“内容不存在或无权访问”，避免泄露对象存在性。
- PostgreSQL 时间使用 `timestamptz`；API 时间为带时区的 ISO 8601 字符串，返回统一 UTC，例如 `2026-09-22T02:00:00.000Z`。业务日期为 `YYYY-MM-DD`，业务时区固定 `Asia/Shanghai`，次日 02:00 按该时区执行。客户端时间只能作为诊断线索。
- 学分、比例及需要精度的十进制量以 JSON 字符串表示，例如 `"10.00"`；后端使用 `numeric`。时间证据与 API 时长使用整数毫秒，Schema 中 `numeric(18,3)` 秒以精确十进制除/乘 1000 映射，不经浮点秒或按整秒四舍五入。计数使用整数，禁止用浮点金额累加。标准时长、有效时长、累计时长使用不同字段，不能用一者反推完成状态。
- `null` 表示没有值或不适用；`0` 表示成功计算出的零。枚举与 `schemaVersion` 由版本化契约约束；预留枚举不能直接启用，提交未启用类型返回字段级业务错误。
- 区间统一采用 `[startAt, endAt)`。日期筛选在服务端按业务时区转换；无任务时间窗时继承项目/学员有效期，不能把无值解释为无限制。

### 1.3 会话认证、CSRF 与即时撤权

登录建立服务端不透明会话，浏览器通过 `HttpOnly; Secure; SameSite=Lax` Cookie 携带，生产使用 host-only Cookie，不把登录令牌放入 `localStorage`。登录、重新认证时轮换会话标识；退出、禁用、软删除、重置凭证和会话撤销使旧会话失效。空闲与最长会话时长是运营配置，具体数值在安全配置评审确定。

写请求校验同源 `Origin` 并携带会话绑定的 CSRF token；无自定义请求头的卸载补报在 JSON 体中携带受限 CSRF token，服务端同时校验 Origin 和会话。跨域策略明确允许名单，不使用携带凭证的任意源。登录失败和找回响应不泄露账号是否存在；记录审计与频率限制，账号锁定阈值不在本稿擅自指定。

每次受保护请求从 PostgreSQL 权威读取账号有效状态和租户权限表 `authz.tenant_authorization_revision` 的 `revision`（`tenant_id` 唯一），API 的 `authzRevision` 映射该值；重新校验节点导航与动作、对象级任命、数据范围。L1/Redis 只能缓存以租户＋用户＋版本键控的不可变策略快照，不用旧 TTL 快照授权；权限版本或 Redis 无法可靠取得时按04文档 fail closed，不临时降级放行。学习开始、心跳、完成、下载和导出领取都不能仅依赖进入页面时的鉴权。当前账号失效或学习权限被撤回时拒收后续新学习证据，保留历史记录。角色配置及任命取消通过共享 UnitOfWork 同步更新 authz 索引和版本，不等待异步事件完成才撤权。

### 1.4 成功、错误、分页与并发

成功信封示例：

```json
{
  "data": { "id": "1439abf9-9655-4869-8231-b205174d44ca", "version": 7 },
  "meta": { "requestId": "9e52794d-44c8-4942-b42c-a376ebd16b7c", "serverTime": "2026-09-22T02:00:00.000Z" }
}
```

拒绝信封示例（HTTP 403 是传输语义，界面不展示“403”或内部码）：

```json
{
  "error": {
    "code": "PERMISSION_DENIED",
    "message": "暂无权限查看此报表，请联系管理员开通权限。",
    "guidance": { "text": "开通路径：管理端－我的企业－角色权限－个人学习详情", "action": "CONTACT_ADMIN" },
    "fieldErrors": [],
    "retryable": false
  },
  "meta": { "requestId": "9e52794d-44c8-4942-b42c-a376ebd16b7c", "serverTime": "2026-09-22T02:00:00.000Z" }
}
```

| HTTP | 语义与前端表现 |
|---|---|
| 400 / 422 | 请求格式或业务字段无效，`fieldErrors[{field,message}]` 定位字段；保留已填表单 |
| 401 | 会话失效，提示重新登录；不得显示学分或报表为零 |
| 403 | 节点/动作/对象权限拒绝，页内友好空状态和可操作开通指引 |
| 404 | 对象不存在、已删除或无可见权限，避免额外披露 |
| 409 | 版本、并发、幂等键冲突，返回 `currentVersion` 或重新预览动作，不自动覆盖 |
| 410 | 预览、签名、挑战或下载票据到期，提示重新获取 |
| 429 | 频率限制，提供 `Retry-After`；保留未确认上报队列 |
| 5xx | 请求失败，允许按幂等规则重试；报表显示错误态，不填入零值 |

列表使用 `limit`（默认 50、最大 200）和不透明 `cursor`，稳定排序包含 ID 作为同值次序；返回 `items,nextCursor,hasMore`。搜索与筛选均在范围约束之后执行；不返回授权范围外的 `total`。我的学习默认 `deadline ASC NULLS LAST, id ASC`，已经毕业的项目不出现在待学习页签。

读资源返回 `version`/`ETag`；更新、状态转换使用 `If-Match` 或 `expectedVersion`。客户端不知道版本时须先读取；匹配失败返回 409 及重载建议。列表批量写入明确为 `ALL_OR_NOTHING` 或逐项结果，不能部分失败却返回笼统成功。

新建、发布、指派、生效、发分触发、审批、导出等命令使用 `Idempotency-Key`。幂等键作用域为租户＋操作者＋规范路由＋键；记录请求摘要和最终响应，同键同内容重放原结果，同键不同内容返回 409。技术建议响应缓存保留至少 7 天，可配置；响应缓存到期之后仍由业务唯一键阻止重复指派、重复奖励和重复结算。心跳使用持久化的 `(sessionId, sequence)`，不依赖通用缓存。

### 1.5 动作与范围

动作按 `<module>.<resource>.<verb>` 命名，例如 `knowledge.course.update`。表中 `.read` 不代表自动拥有下载、导出或敏感字段权限。`AuthzService` 生成结构化 `ScopeSpec`，调用方只能收窄，不能从请求体接受授权谓词或先全量查询再前端过滤。

六种节点范围统一表示为 `ALL_TENANT / DEPARTMENT_SUBTREE / DEPARTMENT_ONLY / SPECIFIED_DEPARTMENTS / MANAGED_SCOPE / SELF`，附带必要的部门或人员引用。T-05已确认：先在各角色/节点内应用人员覆盖，再合并同节点、同动作的有效授权；覆盖仅影响对应角色，不能拆开动作与范围再做全局并集。策略记录该合并版本。对象级任命授予该对象声明的动作，并按T-06派生管理后台及培训中心对应入口，不放大到其他项目或管理模块。

T-06接口约束：有效项目负责人任命使`GET /auth/me`返回可进入管理后台的`managementAccess`及培训中心对应`menuTree`，即使学员基础角色无管理菜单也应成立。`allowedActions`是界面提示，必须绑定节点及来源范围，不代表对所有项目可执行该动作。后台列表、分页/count、搜索、详情、保存和导出由服务端分别应用任命项目集合与动作条件；后台壳、培训中心授权页面及被任命项目直链允许访问，其他模块/项目仍拒绝。若用户另有合法角色，按T-05合并而不反向收窄。撤销任命同步递增`authzRevision`，下一请求重新计算菜单、入口与对象范围；仅撤销对应来源，最后任命撤销且无其他后台授权时关闭入口。

| API ScopeSpec 枚举 | Schema `scope_code` | 含义 |
|---|---|---|
| `ALL_TENANT` | `all` | 租户全部数据 |
| `DEPARTMENT_SUBTREE` | `own_department_tree` | 本部门及下属部门 |
| `DEPARTMENT_ONLY` | `own_department` | 本部门 |
| `SPECIFIED_DEPARTMENTS` | `specified_departments` | 指定部门 |
| `MANAGED_SCOPE` | `jurisdiction` | 人员配置的管辖范围 |
| `SELF` | `self` | 本人数据 |

T-16：授权命令携带managementRoleMembershipId，服务端确认该成员关系属于操作者且具备授权管理及可转授能力；不能拼合不同角色的等级、动作和范围。指定部门includeDescendants默认false；范围覆盖存在但集合为空即无授权，DELETE覆盖才恢复继承。父分类forceChildrenInherit锁定约束创建者及课程覆盖，允许独立时custom仅替换浏览集合，不转授其他动作。

团队成员查询与主管增删项目成员使用 `directManagerId = actorId`，不能由部门树推导。报表仍根据各报表节点的六范围配置决定可见人员，不把“我的团队”谓词覆盖到报表。敏感字段经字段级权限过滤后才序列化，主管默认手机号/邮箱脱敏；导出遵循同一字段授权。

T-07：ScopeSpec附带中央服务计算的allowedCompanyIds；客户人员上限为本公司，内部人员跨客户范围来自有效公司授权。人员列表按当前companyId过滤，学习/报表按事实dataCompanyId过滤；ALL_TENANT、项目负责人任命、直接ID和导出都不能绕过。公司ID仅作待校验的业务字段，客户端不能提交授权公司集合。共同参与一个项目只共享获授权内容，不获得其他公司人员名单、统计数量或附件。项目整体变更若会作用于操作者公司范围外的参与者，必须由覆盖全部影响公司的管理身份执行，不能用隐藏名单绕过影响范围确认。

## 2. 接口目录

下表的 **K** 表示 `Idempotency-Key`，**V** 表示版本校验，**S** 表示服务端派生身份与 `ScopeSpec`；GET 仍需 S。请求中的 ID 均检查租户、对象存在性和引用权限。省略的普通查询返回 DTO，不暴露 ORM 实体。

## 3. 上传、发布和进入学习

### 3.1 上传和媒体就绪

上传状态为 `CREATED → UPLOADING → UPLOADED → PROCESSING → READY`，失败进入 `FAILED` 并携带可读原因。签名只允许指定对象键、内容类型、最大字节数、有效期与分片编号；`complete` 校验实际上传大小、摘要、内容类型和媒体探测结果，异步转码/文档预处理成功才进入 `READY`。未经处理的上传不能通过修改 `assetId` 或伪造时长发布。

持久化落点为files.upload_session/upload_part；实际对象接收且大小/摘要核验成功后才创建files.asset并绑定result_asset_id，重复complete返回同一assetId。资产初始为UPLOADED/PROCESSING，媒体就绪后才READY；状态向API显式映射。取消或过期上传返回CANCELLED/EXPIRED，清理由后台复核无有效引用后执行，不删除被已发布内容或历史版本使用的对象。

视频标准时长以服务端媒体探测为准，不开放手填视频时长。资源版本引用确定的 asset 版本；替换资产不能隐式替换已有学习记录的内容。课程发布检验资源均READY、课程任务结构及权限有效；文档须pageCount>0并绑定可读页清单，零标准时长允许，转换失败/无可读页拒绝发布。课程学分/标准时长响应同时给出所依据的策略版本，计算值不能从浏览器照单全收。

播放票据绑定租户、人员、资源版本、用途、合法入口和必要的学习会话，建议 60 秒有效，客户端按需续签。每个媒体请求还须经受控交付网关或具备在线校验权限/发布版本能力的 CDN 边缘授权；单纯“签名未过期就可访问”的对象存储 URL 不满足下一请求撤权要求。下架即拒绝新的片段请求、会话、心跳和续签；已下载/已开始发送的字节无法撤回。已缓存片段的本地播放不构成继续学习授权，不接受下架后新发生的进度。部署没有上述逐请求授权能力时，须使用受控Nginx网关代理字节、Nest只承担鉴权子请求，不得将纯短签名宣传为即时撤权。内容下载另查 `download` 动作。

### 3.2 草稿、发布与下架

创建页面的“下一步”只推进本地表单；“保存草稿”或显式发布才调用新建命令。编辑使用课程 ID 和草稿版本，不能复用创建路由。已发布版本保持可学，新的草稿不会自动改变学员正在使用的内容。

下架预览返回 `previewId,publishedRevisionId,activeLearnerCount,impactDigest,expiresAt`。确认时重新统计在学人数并校验版本；人数变化返回 409，要求重看具体数字。成功事务改变发布状态、递增访问授权版本并写 outbox；随后新请求即时拒绝，缓存失效消息仅用于加速。下架没有本期审核等待态。

### 3.3 来源与打开即同步

`entryContext` 只有两类合法形态，由服务端校验引用关系：自主入口为 `{"sourceType":"SELF_DIRECTED","sourceObjectId":"课程ID"}`；项目入口为 `{"sourceType":"PROJECT_ASSIGNED","sourceObjectId":"项目ID","enrollmentId":"成员ID","projectTaskId":"任务ID"}`。文档中的“课程ID”等是字段说明，真实报文必须是 UUID。

同人同公司同课从自主和项目进入产生不同来源的学习记录；不同公司不复用记录/轮次，也不把旧公司的完成事实同步给新公司。`course-opens` 记录去重后的浏览行为，不新增长度为零的有效学习事实。开启同步且已有可信历史完成时，在当前项目来源记录中产生 `completionOrigin=SYNC` 的完成事实；完成人次增加、学习人次和时长不增加。同步调用不能绕过课程发布、学员指派和当前学习时间窗。

| API 字段/枚举 | Schema 映射 | 约束 |
|---|---|---|
| `sourceType=SELF_DIRECTED` | `source_type=self_directed` | `sourceObjectId=course_id`，`sourceObjectType=COURSE` |
| `sourceType=PROJECT_ASSIGNED` | `source_type=assigned` | `sourceObjectId=project_id`，`sourceObjectType=PROJECT`；另存成员与项目任务ID |
| `learningRoundId`、`learningRoundOrdinal` | `learning_round_id` UUID、`training.learning_round.ordinal` | ID 用于业务唯一键；ordinal 只作轮次展示，本期默认1，不能用常数1代替UUID |
| `enrollmentId`、`projectTaskId` | `project_enrollment_id`、`project_task_id` | 同项目多次挂同课可区分，不以courseId替代任务ID |
| `sourceLevel=TASK/STAGE/PROJECT` | `source_level=task/stage/project` | 奖励另带 `sourceObjectType=COURSE_TASK/PROJECT_TASK/STAGE/PROJECT` 对应小写值，不能只用层级猜对象表 |
| 保留 `MERIT/MENTORING` | `excellence/mentorship` | 仅映射保留值，不启用本期功能 |

独立面授的来源对象为面授ID；项目面授来源对象为项目ID，另携带成员/项目任务ID。面授时长通过StudyPublic的类型化来源写入：学员关联offline_enrollment，讲师关联有授课任命的duration_verification；两者带固定人员快照、dataCompanyId和learningRoundId。不伪造课程记录，也不为讲师伪造学员参训关系。

T-19：课程自身学分跨入口共用一次永久资格；项目任务/阶段/项目奖励独立，可与课程学分叠加。同步完成沿用同公司合法完成事实，只补未领来源，不凭新建来源记录重复发课程奖；学习人数与时长仍不因同步增加。

## 4. 学习会话与进度上报详细契约

### 4.1 开始与单活

打开课程不自动播放。用户点击“开始学习”后，调用 `/study/sessions`；服务端检查账号、可见范围、课程状态、指派与任务引用、时间交集、媒体就绪、会话单活和所采用的计时策略。学习人数按已接受的学习行为及模块×动作矩阵判定，不能因刷新播放页、申请播放 URL 或预加载媒体增加。

同租户同人员只允许一个活跃内容会话。数据库中的活跃会话/排他约束负责最终正确性，Redis 租约负责快速拒绝和续期；两个并发开始请求不能都成功。刷新同一页面可根据服务端返回的会话恢复；另开内容返回“同一时间只能学习一个内容”。如后续提供“结束前一学习”功能，必须显式结束前会话并失效旧租约，不能仅覆盖 Redis 键。

### 4.2 20 秒心跳、服务端校验与持久化 ACK

心跳上报片段和证据，不上报可信“本次应加学分/应加时长/已经完成”。

```json
{
  "sequence": 1,
  "reportId": "e95e326d-c742-4886-b436-f73b789f23dd",
  "pageInstanceId": "606630f5-47e2-4c22-870b-c605609faad5",
  "clientMonotonicElapsedMs": 20000,
  "mediaPositionMs": 60000,
  "playbackRate": "1.00",
  "playState": "PLAYING",
  "visibility": "VISIBLE",
  "segments": [{ "fromMs": 40000, "toMs": 60000, "elapsedMs": 20000 }]
}
```

服务器按下列顺序处理（具体数据库加锁顺序以09为准）：

1. 校验本人、有效租约、当前账号/权限/课程状态及学习时间窗；对同一序号相同摘要重放 ACK，不再次计数。同序号不同报文返回 409；跳号返回 `expectedSequence`，客户端先补前一条。
2. 使用服务端收到时间、上一次服务端 ACK 时间、已授予的租约窗口、单调耗时变化、媒体位置和允许倍速校验片段。客户端 wall clock、页面可见性、鼠标事件只作证据，不能单独证明真实学习。
3. 首次完课前禁止拖拽时，拒绝不连续跳跃或超出合理播放速度的新增区间；客户端进度条禁用只是体验层。暂停、缓冲、已失效、未确认挑战后的片段不按正常播放计入。
4. 在PostgreSQL事务中追加可审计上报、更新lastAcceptedSequence与证据摘要；用已确认有效证据检查阈值，视频必要在线确认已完成时自动判定，文档只更新已验证页进度并等待显式complete，并在同一UnitOfWork提交完成事实及即时账务。任一步失败回滚，不能先提交“已完成”再等待发奖。
5. 事务提交成功后返回已持久ACK、确认/暂存进度及完成/奖励结果；视频无须等待客户端另发complete；文档达到页阈值后仍须显式complete。只进入Redis或内存不能返回“已保存”；明细聚合可后续刷新，但不能等10分钟投影才判断完成或发奖励。热数据按session_id分区仍保持跨日序号唯一，归档后终态和旧序号处理见09，不接受旧会话作为新证据。

```json
{
  "data": {
    "acknowledgedSequence": 1,
    "acceptedAt": "2026-09-22T02:00:20.080Z",
    "persisted": true,
    "state": "ACTIVE",
    "confirmedProgress": { "validatedProgressMs": 40000, "version": 8 },
    "tentativeProgress": { "provisionalProgressMs": 60000 },
    "effectiveDurationMs": 40000,
    "cumulativeDurationMs": 40000,
    "challenge": null,
    "nextSequence": 2
  },
  "meta": { "serverTime": "2026-09-22T02:00:20.080Z" }
}
```

以上示例采用“超时使本次会话无效”模式，因此新片段尚属暂存。API `tentative/confirmed` 分别映射 `study.progress_event.validation_state=provisional/validated`，作废为 `invalid`。普通已验证片段、当前页面的暂存播放点与财务已确认事实必须分别呈现，不能把待确认片段提前发分。片段区间用于防拖拽、乱序和异常证据校验，不能自行把完成算法改为“全片区间并集覆盖”。完成阈值使用服务端累计有效观看量与批准的标准时长 N% 规则；T-12：合法重复片段可推进未完成进度；重复报文、拖动与并行片段不可。保存wallElapsedMs/mediaAdvanceMs/playbackRate/policyRevision，实际播放量×倍速得到内容学习量：5分钟内容2倍速完整播放实际2.5分钟/有效5分钟；实际播放5分钟可对应10分钟内容量，但有效时长仍封顶于内容标准时长，累计可增长。

### 4.3 防挂机的两种模式

| 模式 | 服务端行为 | 学分/进度后果 |
|---|---|---|
| `PAUSE_UNTIL_CONFIRM` | 生成随机 challenge，记录 `issuedAt,deadlineAt`；确认前冻结可接受新片段，客户端停止播放 | 已确认片段保留，待确认后的播放不计入；及时确认后继续 |
| `INVALIDATE_SESSION` | 全会话保留开始前 baseline，新片段暂存；未在服务端截止时间前确认，状态变为 `INVALIDATED` | 本次暂存进度作废、恢复 baseline，本次不增加时长或学分；不影响以前会话已获得的权益 |

确认接口携带 `challengeId,nonce,lastAcknowledgedSequence`，以服务器接收且验证通过的时间 `confirmedAt` 判定准时，不信任客户端声称“刚才点了”。过期确认返回 `SESSION_INVALIDATED` 的可读提示。定时清理负责没有后续请求的超时会话；即使清理任务延迟，后续写请求也会即时检查截止时间，不能利用调度延迟补确认。

在第二种模式下，达到完课阈值时先完成必要的在线确认，再把暂存证据提交为已确认并自动结束该有效会话，随后触发完成和奖励；不能先发分再等待一个可能让整个会话无效的挑战。结束/重新开始不能清除未响应挑战来规避判定。后续重复观看创建新会话，不能使上一已确认会话回退。

挑战频率、可确认秒数为可版本化运行参数；文档完成使用T-12已定页证据及比例阈值，完成比例取课程配置。浏览器端证据校验用于约束明显异常，不声称可以证明人的真实注意力。

### 4.4 卸载补报、重试与恢复

客户端按约 20 秒生成递增序号报文，先把待发送报文写入该账号、租户与会话隔离的本地持久队列，再发送。收到持久化 ACK 才删除队列项。`visibilitychange`/`pagehide` 等触发 `flush`，优先使用 keepalive 请求或 `sendBeacon`；`sendBeacon=true` 只说明浏览器接受排队，不代表服务端已入库。

`flush` 与 heartbeat 共用幂等键、证据校验和事务入口，不能另写一条可无限补时间的快速通道。网络恢复后按序重试；服务器只接受仍在授权租约与允许迟到窗口内的有效片段，超过窗口不把整段离线时长补成学习。客户端应重新拉取 ACK 序号与权威进度，对已接受序号移除队列，对失效片段解释无法确认原因。

退出账号后不得把旧账号队列发给新账号；本地队列不存密码、Cookie 或播放签名。正常关闭、网络正常且最后请求到达、未触发挂机失效时，验证 30 秒观看可恢复到相应进度；浏览器强杀、设备断电、存储清除或网络断开时，无法承诺最后一段绝对不丢。可保证的是：服务端已 ACK 的证据持久可恢复，未 ACK 片段尽力补报且不重复计时；ACK 暂存证据仍可按已批准防挂机规则作废，不等于保证暂存进度绝不回退，更不等于提前确认课程完成。AC-E-04 须按这些边界拆分测试。

### 4.5 结束、完成与奖励响应

`end` 原子处理 `finalReport` 后结束租约，返回 `ENDED / PAUSED / INVALIDATED`。视频在确认进度、挑战确认和有效结束时自动尝试完成判定，complete可作幂等补试；文档complete是达到页比例后的必要显式确认。两者都不是客户端设置完成状态。后端重新校验媒体版本、完成策略、挑战、序号、有效片段、当前发布状态和项目任务窗。仅播到最后一帧、浏览器宣称 100% 或手填时长都不能完课。

完成后返回 `completionId,completedAt,completionOrigin,progressVersion,rewardReceiptIds,rewardState,feedbackEligible`。即时学分通过完成领域事件的关键同步订阅者调用 `OperationsPublic`，和完成事实共用 `UnitOfWork`；奖账失败则不能返回“完成且到账”。可返回暂存已保存、完成提交待重试的明确状态，客户端重复提交不会重复奖励。标签和站内提醒可走 outbox；标签授予唯一键为人员＋标签＋授予来源，合并时保留来源关系。

固定的完成判定只发布类型化结果，不硬编码学分、标签、反馈 UI。V1 关键订阅者承担应即时到账的学分，非关键订阅者承担标签/消息；新增证书等订阅者不改完成条件。重复有效学习可增长累计时长，已完成权益不会再次发放。T-12文档用去重有效页比例＋显式确认，不能用打开文档冒充完成。

### 4.6 文档页证据与显式完成

文档会话返回resourceRevisionId、readablePageCount、completionThreshold、validatedPageCount及requiresExplicitComplete=true。心跳携带`pageEvidence[{pageNumber,loaded,visibleElapsedMs}]`，服务器核验已发布清单、受控页请求、会话/序号、合理可见耗时和防挂机结果。页号越界/资源版本错配返回422，伪造无加载/失效会话证据拒绝；每次最多100页证据是请求大小限制，可分批上报。

有效证据写study.document_page_evidence；同记录/任务/资源版本按DISTINCT pageNumber计算进度，重复同页不增加比例。ACK分别返回暂存/确认页数及服务端计算比例，防挂机未通过的页不进入确认计数。达到配置阈值后学员点完成，complete复核证据并原子发奖；同步完成例外有独立completionOrigin。零标准时长可按页完成，时长仍0。页面可见证据用于拒绝明显异常，不声称可证明人已阅读理解。

## 5. 指派、时间交集与记录

### 5.1 指派的重复与并发

手动指派、主管添加、规则扫描和动态用户组联动都调用TrainingPublic.EnrollParticipants。项目＋人员＋公司＋学习轮次保证有效成员不重复；首次加入方式为MANUAL/AUTOMATIC/MANAGER_ADDED/DYNAMIC_GROUP，joinedAt/addedBy/规则版本由服务端填写。多个命中来源在enrollment_source并存，组成员退出按来源更新，不能直接抹掉人工加入或历史学习。实时/近实时组事件与每日规则扫描独立，失败有检查点和补扫。

批量指派采用逐项结果：`created`、`alreadyEnrolled`、`rejected` 分开，拒绝项给出“人员已停用”等业务原因，绝不把不在授权范围内的完整档案带回。并发手动和自动指派命中同一个人时，数据库唯一约束后读回已有成员，只有一次来源创建与一次指派提醒。T-14人工移除不删除持续生效规则，下一次命中可恢复同公司同轮次关联并保留原计划/记录；页面先提示可能恢复。不能删除历史唯一键制造新资格。

自动扫描以 `projectId + ruleRevisionId + businessDate` 标识一次规则运行，检查点支持分批恢复；每日定时和人工补跑共享执行器。规则 OR/AND 只针对已配置的部门、岗位、用户组、入职时间条件；空规则不得被解释为自动纳入全租户。扫描通过 `OrganizationPublic` 带范围读取符合条件的启用人员，不能跨模块查询人员表。相同业务结算日期的时区由服务端固定。

### 5.2 时间和状态

周期项目创建成员时固定该人的 `plannedStartAt,plannedEndAt`；默认开始时间由服务器确认，不能在首次学习时偷偷重置。绝对时间项目成员共享同一项目窗口。学习资格为项目窗口/学员周期与任务窗口交集，并检查项目自动结束策略；任务无窗口时不额外收窄。时间到达结束点后拒绝开始和新片段，不能靠已有页面继续累计。超过截止的片段只承认截止前可验证部分，不把整个心跳一律加满。

完成、逾期、毕业分开返回：`completionState`、`overdueState`、`graduationState`。手动出师不写任务完成、不发并未满足触发条件的奖励。项目中任一任务进度大于零即可显示学习中；计算分母仍使用“是否计入完成度”和完成标准，必修与计进度不能合成一个字段。

T-08选择保存拦截：任务非空时间超出项目已定义的固定时间区间，返回422与`fieldErrors`（TASK_WINDOW_OUTSIDE_PROJECT），不保存越界草稿或用黄色警告放行。复制/批量保存/发布走同一校验。周期模式没有全局绝对区间时不虚构日期，在学员计划建立/调整时复核真实区间并指出不可安排的任务；实际学习始终取三层交集。T-13：首发项目/阶段完成条件任务非空；已发布删除最后条件任务对既有参与者可正向完成，只补合资格的未领阶段/项目奖，并置enrollmentGate=NO_COMPLETION_TASKS。人工/规则/组新增关联均返回PROJECT_HAS_NO_COMPLETION_TASKS，不写空项目成员；已有成员身份转换按T-14办理。补足大纲后恢复OPEN。毕业不随完成回退撤销，毕业项目从历史/消息入口访问新增任务。

## 6. 大纲影响预览与确认生效

### 6.1 不变量和身份锚点

- `project_task.id` 消失是删除；ID 保留而引用内容 ID 改变是替换；只改名称、顺序、时间、必修属性或学分数值不是替换。内容和任务版本都保留历史可追溯引用。
- 新增必修可能造成完成状态回退，分母按当前可见大纲立即重算；删除未完成必修可能使状态前进，并补发此前没有兑现的阶段/项目权益。
- 删除或替换对应必修任务时，按PROJECT_TASK来源追回该项目任务的已发权益；独立COURSE_TASK自身学分及其他项目奖励不跟随追回，阶段/项目奖励保留。不擅自把既定 D-42 追回范围扩展至所有选修任务。已有任务只改学分数值不追回也不补发，今后第一次满足权益者使用新规则版本。
- 预览、取消、预计算都不能更改学员可见版本、进度、学分余额或向学员发送已经生效的提醒。发布成功时当前完成状态、分母、应追回/应补发账务和 `visibleOutlineRevisionId` 必须一致提交。
- 不以每 10 分钟的管理投影刷新替代即时权威状态。报表历史事实可保留原完成事件；当前项目详情应读取已生效新大纲的状态，不混用旧分母和新任务列表。

### 6.4 准备与原子生效

变更状态为 `PREPARING → READY_TO_COMMIT → APPLIED`；还可进入 `NEEDS_RECONFIRMATION / CANCELLED / FAILED`。长时间处理返回 202 和 `changeId`，页面显示“正在准备，当前大纲仍有效”，而不是“已生效”。实现顺序如下：

API与数据库显式映射为：`PREPARING→preparing`、`READY_TO_COMMIT→rechecking`、`APPLIED→committed`、`NEEDS_RECONFIRMATION→needs_reconfirmation`、`CANCELLED→cancelled`、`FAILED→failed`，详见[Schema生效状态表](02_数据库Schema设计.md)。需重确认时释放屏障并保留旧版，记录新预览及历史确认；再次确认沿用同一项目/目标版本的changeId，不能归入普通失败后自动重试。

1. 保存不可变候选大纲和重算计划，分批预计算学员的新三进度、回退/前进结果及账务候选；候选账务存 `operations.activation_ledger_intent`，不计余额。此时都不可见，不把一万人重算先塞进一个未经验证的长事务。
2. 通过变化序号/检查点增量补齐计算期间的学习与成员变化；这只是更新候选，不代表可以改变用户确认过的影响。影响摘要变化进入 `NEEDS_RECONFIRMATION`。
3. 最终切换短暂取得该项目写入屏障，阻止新的成员、任务结果、当前项目进度提交穿越切换边界。其他项目对同一账户的写入不受这个屏障保护，因此仍须在账务层复核账户版本。
4. 一个 `UnitOfWork` 内由 `TrainingPublic` 校验可见/候选版本及检查点，由 `OperationsPublic` 按确定顺序锁定受影响账户、复核余额及待抵扣，写入任务追回/阶段项目补发和审计流水；各模块只写自己的表。同步写入当前生效进度状态或其权威代次引用，再切换 `visibleOutlineRevisionId`，写 outbox。
5. 任一步失败，事务回滚且旧版本继续有效；版本或金额变化需重新确认。提交成功才标记 `APPLIED`，后续页面读取必须使用新版本。失败重试依据 changeId、奖励权益及原交易追回唯一键，不重复记账。

“短事务”是性能目标，不是本稿证明。5 万人批量状态切换、账户锁和账务写入是否能接受，必须在 B4 的代表性数据、并发完课和跨项目同账户竞争下实测。若不满足性能/锁等待目标，应评审更长发布等待或另行调整业务语义；本稿不默许将到账改成异步。准备期可等待，发布成功后不能出现“进度已回退但学分调整还没开始”的中间态。

### 6.5 通知与查询

事务提交后 outbox 发出变更结果；站内消息异步投递并有可查状态，但消息失败不能回滚已提交业务。`GET change` 返回 `state,appliedAt,oldRevisionId,newRevisionId,appliedImpact,notificationDeliveryState`，不使用 `financialSettlement=PENDING` 隐藏未到账情况。

回退通知包含项目名称、变化原因、还差哪些任务和可跳转入口；追回通知含来源任务、原发放、实际扣回及待抵扣；正向完成通知含因哪次大纲变更达成完成和补发明细。文案由结构化事实生成，不能只写“状态已变更”。本期仅站内触达，不声称已送达飞书、钉钉、短信或邮件。

## 7. 学分、权益与次日结算

### 7.1 奖励载荷与权益幂等

奖励配置使用集合：`amounts=[{"currency":"CREDIT","amount":"10.00"}]`，并保留 `tier=BASIC/EXCELLENT` 与 `sourceLevel=TASK/STAGE/PROJECT/MERIT/MENTORING`。本期只执行 credit、基础档、任务/阶段/项目三级；分组不构成奖励源。后台拒绝未启用币种、优秀档或评优/带教命令，不能因结构预留而自动开放功能。

T-09：阶段/项目奖励资格跟随项目已配置且发布锁定的完成标准。项目为ALL_REQUIRED时检查相应阶段/全项目必修，为ALL_TASKS时检查全部任务；返回的eligibilityPolicy为派生只读值，拒绝另设矛盾条件。任务级奖励仍按类型的完成/合格语义；不能因提交作业就视为可发阶段奖。

API 十进制字符串映射 `numeric(18,4)` 金额、`numeric(9,6)` 比例；入参超过已允许精度返回字段错误，不能静默截断。示例 `"10.00"` 与 `"10.0000"` 表示同值；实际舍入发生在已批准规则的指定层级，不发生在JSON序列化阶段。API `currency=CREDIT,tier=BASIC/EXCELLENT` 分别映射数据库 `credit,base/excellent`；未启用档位仍拒绝业务写入。

T-19：资格键共同包含tenant＋person＋dataCompany＋tier；课程奖另含稳定courseTaskId＋resourceId，项目任务奖另含projectTaskId＋contentId，阶段/项目奖另含稳定stageId/projectId。入口、学习轮次、课程/大纲/规则版本只作审计，不制造新资格。多币种结果按entitlementId＋currency去重；未满足资格不永久占位，0金额资格记终态。详细规范与替换/换回语义见02§10.2。课程1分＋项目4/2/3分为10分；课程奖已领时只补项目9分，各来源独立。

普通完成与大纲正向重算走同一 `OperationsPublic.GrantEntitlement`。已兑现权益返回原交易；回退后再完成不再次发阶段/项目奖。删除/替换对应必修任务通过 `RecoverTaskEntitlement(originalTransactionId,changeId)` 追加追回分录，该命令必须校验 D-42 适用来源，不删除原流水、不修改原奖励金额。任务被删后，流水仍以名称快照和历史版本可读；跳转无权限时只显示当前用户有权看到的来源摘要。

### 7.3 预置扣减与时间

调度以 Asia/Shanghai 的下一业务日 02:00 启动，结算键为租户＋公司＋人员＋规则＋来源对象＋学习轮次＋应结算业务日期。定时任务重启、补跑、队列重复不重复扣。02:00 是开始处理时间，不能不经规模验证承诺所有人 02:00:00 已完成；返回 `startedAt,completedAt,processedCount,failedCount`，失败项单独重试。23:30 尚未扣分是正确状态，已完成且到账与报表投影延迟分别解释。

### 7.4 标准学分、奖励数值和历史重算的边界

🔴 T-10为我方定义，原站课程级聚合从未验证（G-06），不得声称“与原站一致”。目标接口按以下规则验收：每任务按max(标准分钟×系数,保底)计算后HALF_UP两位，再求课程总额；默认系数/保底0.1可配。API返回calculationPolicyVersion、minimumScope=TASK、roundingMode=HALF_UP、roundingScale=2及逐任务明细；两个零时长任务分别0.10，课程0.20。项目配置奖励与课程标准值仍为不同来源。

T-10明确ALL_CONTENT仅更新内容标准值及后续首次发放；响应给出updatedContentCount与postedLedgerAdjustmentCount=0，不调整历史已发权益。单个项目任务仅修改奖励数值时，严格按 D-42 保留旧交易、新完成者采用新值，不把“重算内容标准学分”自动当作重发所有历史学分。

## 8. 面授详细规则

### 8.1 场次、签到和围栏

四参数独立保存为 `checkInBeforeStartMinutes,checkInAfterStartMinutes,checkOutBeforeEndMinutes,checkOutAfterEndMinutes`。签到窗口为场次开始前/后指定分钟区间，签退窗口围绕场次结束；服务器使用收到请求的时间判定，不接受客户端提交一个更早的签到时间。每场次可分别要求签到/签退，只启用的动作都满足才算该场次考勤完成。

四参数是配置单位的明确例外：API 以整数分钟输入，映射数据库 `check_in_before_seconds/check_in_after_seconds/check_out_before_seconds/check_out_after_seconds` 时精确乘60；返回时按配置单位还原，不和学习时长整数毫秒混用。

扫码载荷含场次、动作、随机数、服务器到期时间和签名，不能用持久不变的裸场次 ID 当考勤码。提交时验证本人正式参与关系、场次归属、方向、码有效期和防重放范围。多人可扫描同一当期场次码，但同一人同动作只记一次。

位置载荷为 `latitude,longitude,accuracyMeters,positionCapturedAt`；服务器按已发布围栏中心和半径计算距离，并验证定位新鲜度/精度是否符合批准策略。缺少定位、定位失败或范围外返回明确失败，不默认为签到成功；不能将浏览器位置视为绝对不可伪造的证明。T-17半径按场次配置；定位新鲜度/精度为运行参数，响应明确拒绝原因。负责人可通过attendance-corrections带理由/原事件补录，保留定位失败证据，不修改历史请求为定位成功。

### 8.2 固定请假与考勤/成绩完成

请假状态为 `PENDING / APPROVED / REJECTED`；面授配置明确单级审批人（面授负责人中的指定人），所有决定保存操作人、时间、原状态与意见。后端检查待审批状态和审批身份，重复同一决定重放原结果，并发相反决定返回 409。获批请假独立显示，不计缺勤，不进入未签到催促名单；T-17明确请假不等价于完成场次考勤，不满足成绩条件，也不据请假自动完课发奖。

完成条件限定两项 `ATTENDANCE_COMPLETED`、`SCORE_RECORDED`，组合 `ALL / ANY`，至少选一项。无任何场次开启签到/签退时，返回 `ATTENDANCE_COMPLETED` 不可选及“所有场次均未设置考勤”原因。成绩录入只验证成绩字段、录入权限与人员关联，不凭空增加通过线。修改成绩和考勤事实有审计与版本，其结果重新进入同一完成判定器。

### 8.3 时长推送和双向评价

`durationDeliveryMode=IMMEDIATE/AFTER_VERIFICATION`。标准授课时长发布后不可改；`actualDurationMs` 是核实后的实际值，不覆盖标准时长。完成面授与时长已下发分离：核实模式下可有完成事实、时长状态 `PENDING_VERIFICATION`，核实后由统一时长发放策略写入学员/讲师记录。即学即推在有效完成事务内创建发放凭据，幂等来源键包含面授、公司、人员、角色、记录来源和轮次。

T-17固定评价方向为LEARNER_TO_INSTRUCTOR/INSTRUCTOR_TO_LEARNER；rating整数1～5，comment≤500字。每方向/作者/被评价人一份当前答卷，修改带expectedVersion并追加历史；面授结束前可改，结束后只读。讲师凭授课任命进入受限评价，不开放独立讲师管理中心；跨公司关联仍需受限评价能力及公司边界，不开放全员名册。

面授结束时，核实下发模式触发负责人站内提醒。挂载为项目任务的面授完成通过 `OfflinePublic`/领域事件向 training 提供完成凭据与来源，不由 training 读取考勤、请假或成绩表拼装判定。面授完成→项目任务/阶段/项目即时判定→应发奖励的关键订阅在同一 `UnitOfWork` 同步执行；标签、通知和报表随后异步消费。

## 9. 报表、导出和数据时效

### 9.1 查询契约

三张报表共享 `filters,columns,scope,metadata` 结构，源自 report 自有投影；投影输入只能是版本化事件或拥有模块的 `Public` 读取接口。字段字典同时列出业务名称、单位、统计口径、可选性和敏感权限，不把“人次”改名成“人数”。

响应例：

```json
{
  "data": {
    "items": [],
    "metrics": {
      "completionRate": { "value": null, "unit": "PERCENT", "state": "NOT_APPLICABLE", "reason": "覆盖人次为零" },
      "learningPersonTimes": { "value": 0, "unit": "PERSON_TIMES", "state": "VALUE" }
    },
    "dataState": "EMPTY",
    "nextCursor": null
  },
  "meta": {
    "dataAsOf": "2026-09-22T01:59:40.000Z",
    "generatedAt": "2026-09-22T02:00:00.000Z",
    "refreshPolicy": "NEAR_REALTIME",
    "timezone": "Asia/Shanghai",
    "metricDefinitionVersion": 1
  }
}
```

正常值、真实零、无数据/不适用和失败四态区分：取数失败直接返回错误信封，不构造全零 metrics，也不把缓存旧值冒充当前值。若展示历史缓存，必须明确标记旧数据时间与失败提示，不能继续显示为正常最新状态。

报表按记录写入时的主部门/岗位快照归属历史事实；`personStatus` 默认 ENABLED 是查询时的当前人员状态筛选，以满足禁用后默认排除、选择禁用可查历史。两者在元数据中分别说明，避免用“快照状态”替代当前启用过滤而造成禁用后仍默认出现。当前权限范围仍按当前授权求值，不因为有旧部门快照就保留已撤销访问权。T-15当前组织/角色范围先决定可查人员，历史公司上限再约束事实，最后按历史部门分组。旧主管不自动留权，新公司不自动读取旧公司事实。当前项目指标按当前正式身份；已结算历史按当时参与身份及变更审计复现，不由今天转旁听改写历史。组织人数统计只含主部门并明确是否含子部门。

### 9.2 时效五层及权威状态

| 数据 | 契约时效 | 使用限制 |
|---|---|---|
| 学习证据上报 | 约 20 秒＋卸载补报 | ACK 必须持久化，不承诺未收到尾段绝不丢 |
| 当前完成/学分 | 判定成功事务即时 | 不等待管理报表投影；成功须已写账 |
| 管理端任务进度投影 | 每 10 分钟刷新，可附当前权威读取入口 | 不用于学习放行、发奖或大纲立即分母规则 |
| 明细报表/汇总看板 | 明细准实时；汇总 T-1 | 分别返回 `dataAsOf,refreshPolicy`；延迟告知 |
| 逾期扣减 | 次日 02:00 启动批处理 | 返回实际任务进展，不假定整批瞬时完成 |

学员与报表读取同一时长定义及投影版本；未刷新时显示更新时间/待同步提示，不给学员端填一个“0 分钟”而报表已有非零值。任务进度 100% 与时长聚合尚未刷新可同时成立，时长不是完成事实的替代品。

### 9.3 导出和重新鉴权

统一创建 `exportId`：小于一万行可在请求内快速准备并直接返回 READY，同一契约也可返回 QUEUED/RUNNING；超过一万行明确异步状态或允许范围限制，不能无提示挂住请求。状态为 `QUEUED / RUNNING / READY / FAILED / EXPIRED / REVOKED`。使用者在下载中心查看，不需另行更换接口。

创建时保存规范筛选、已授权列、当时范围摘要、报表定义版本和快照水位。worker 执行时重新校验账号和当前 `.export` 权限，以创建范围和当前范围的交集生成文件；若缩小将改变用户已确认的导出含义，直接要求重新导出，并给出原因，不生成一个不解释的部分文件。每行经过当前范围与历史指标口径区分后的授权过滤，敏感字段在生成前脱敏。

领取任务、换取票据及实际 GET 文件时均重新鉴权。用户被禁用、导出动作失效、相关范围/敏感字段权限变化，旧文件进入 REVOKED 或拒领并要求重新生成；不能认为“文件已经生成”就永远有权下载。`GET /report/downloads/{ticket}` 由应用鉴权后代理对象存储流，或使用等价逐请求鉴权网关，不向客户端暴露可绕过撤权的长寿命对象存储链接。下载已开始的字节无法回收；下一次领取和下载请求必须重新校验。

这是进程内契约，不是额外的公网路由。输入统一包含可信 `TenantContext,ActorContext,ScopeSpec,correlationId`；写入另有 `commandId,expectedVersion,UnitOfWork`。定时任务使用范围受限的系统主体及业务原因，不用无范围的“超级管理员上下文”绕开校验。

### 11.3 顺序、重放和运维

- 实体aggregateVersion与公开流streamSequence分别递增；流身份为tenantId＋ownerModule＋aggregateType＋aggregateId。一个实体版本可以发多个事件，不用row_version推断“缺了一条消息”。状态投影不被旧版本覆盖；增量事实按eventId/来源区间去重，不以最大版本丢弃尚未处理的旧增量。
- 消费者发现缺口后暂存或拉取拥有方公开快照＋变化水位；跨 aggregate 无全局顺序承诺。大纲变更事件带 `outlineRevisionId/changeId`，进度投影不能把旧任务事件无条件套到新分母。
- 严格顺序消费者由完整流游标判断缺口；只订阅部分类型的消费者不能对被过滤事件的序号无限等待。outbox_delivery逐消费者持久化交付状态，inbox成功回执才证明处理完成；Redis队列丢失可重排未完成交付，published_at非空不代表可忽略。见09的重放与重建协议。
- 重试使用有界退避；超过阈值进入可检查失败队列，保留失败原因、下次重试、相关 commandId/eventId。阈值、保留时间和告警目标由运行配置确定。工作台不得把投递失败显示成业务完成失败或悄悄吞掉。
- 人工重放需专门运维动作权限、理由与审计，保留原 eventId；业务纠错使用新的补偿命令与事件，不能改旧 eventId 伪装重试。禁止直接改账本余额或删除 outbox 来“修复”。
- 报表重建只能重放投影订阅者，不把所有事件重新广播触发发奖。奖励订阅者即使被重放，也有独立权益唯一键防重复。
- 部署期间兼容当前和上一事件版本；新增可选字段不破坏旧消费者，删除或改语义发布新的事件类型版本。事件 schema 与 API schema 应分别维护变更记录。

## 14. 开发交付和验证要求

本稿批准后生成版本化 OpenAPI/JSON Schema 与事件 schema；客户端 DTO 可由 schema 生成，但事件与数据库实体不能直接复用为公网返回值。实现任务以批准的契约为输入，本文件不是实现代码。

契约验证至少覆盖：

1. 浏览、同步完成、真正学习三种行为分别产生正确人次；隐藏课程在合法项目入口可学；下架后心跳/续签拒绝。
2. 并发开始只有一个会话成功；同序号重放不重计，同序号改报文拒绝；ACK 后应用崩溃可恢复；无 ACK 尾段按补报边界处理；挑战以服务器时间判定且第二模式可回退。
3. 登录禁用和权限撤销在另一应用实例的新请求生效；对象越权、跨租户、主管非直属增删被拒；报表六范围与团队直属范围互不替代。
4. 手动与自动并发指派、重复完成、重复结算、重复outbox投递都无重复业务效果；失败可定位与重放；未确认的策略组合不能被默认启用。
5. 大纲取消零副作用；过期/旧版本/学习进度变化/跨项目账户余额变化必须重预览；删除/替换对应必修任务按原交易追回；改学分值不追补；正向完成只补未发权益；余额不足生成待抵扣。
6. 预计算过程中仍能读旧版本；发布成功后状态/分母/账本一致；注入最终事务失败后全部不生效；不能用消息或10分钟投影延迟掩盖原子性错误。
7. 面授第16场拒绝，签到四参数独立，扫码围栏与时间都在服务端检验，获批请假不催促不记缺勤，AND/OR完成与成绩录入按规则，核实模式不提前下发时长。
8. 报表请求失败不填0，零分母为`--`，历史主部门不漂移；生成及领取时撤权都拒绝旧导出；导出与所选字段/脱敏一致。

批次依赖：B3 首次发奖就必须使用统一来源权益和账本；B4-16（可追溯流水）必须先于 B4-14（大纲重算）完成，不能先用余额加减后补来源。性能验证应包含约定硬件上的心跳平均/突发负载、持续稳定性、5万人候选扫描、同账户竞争以及大纲最终切换锁等待；具体容量和耗时以测量报告为准，不能把本稿的接口可行性描述作为压测结论。
