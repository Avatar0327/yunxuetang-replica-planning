### 【已验证】V-23 结论：「课程总量」与「课程管理列表」是两个不同口径
| 口径 | 值 | 含义 |
|---|---|---|
| 首页看板「课程总量」 | 129（取证时点） | 租户内课程总数 |
| 分类课程数合计 | 132（含本次新建的 2 门测试课程） | 按分类归属统计 |
| **课程管理列表** | **1 → 3 门** | **admin 的可管理范围**（非全量） |

**【已验证】** 「课程管理」列表呈现的是**管理数据范围**，不是全量课程。
→ **规划含义（重要）**：报表/看板的「总量」与管理列表的「可见条数」**必然不一致**，这是**正常行为而非缺陷**。
需求基线与验收场景必须显式说明：**管理列表受数据权限约束，统计指标不受**（统计另受其自身的数据权限节点约束，见 E006 §1）。

## 3. ⭐⭐ 分类权限模型【已验证】——课程可见范围的根

「编辑分类」弹窗的完整权限模型：

### 3.1 基本信息
| 字段 | 值/说明 |
|---|---|
| 所属分类 | 主课堂（分类挂在企课堂下） |
| 创建人 | `管理员/admin`，标注 **「创建人有该目录的所有权限」** |
| 分类名称 | |
| **设为公开** | **「公开分类对全平台开放浏览权限，子分类会同步设为公开分类」** |

**【已验证】** 「设为公开」是**一键全平台开放**的快捷开关，且**级联到子分类**。

### 3.2 权限主体（3 类预置 + 1 类自定义）
| 主体 | 说明 |
|---|---|
| **超级管理员 & 分类创建者** | 预置主体 |
| **课堂管理员** | 预置主体（对应企课堂的管理员） |
| **课堂成员** | 预置主体 |
| **添加用户权限** | 自定义指定用户/范围 |

### 3.3 权限动作（5 项，每个主体独立配置）
`全选` / **`分发`** / **`维护`** / **`浏览`** / **`允许下载课件`** / **`App缓存课件`**

**【已验证】关键**：权限动作区分了 **浏览（看）**、**维护（改）**、**分发（推送给他人学）** 三种语义，
另有两项**内容安全相关**的独立开关：**允许下载课件**、**App缓存课件**。
→ 呼应 E014 §7 的信息安全设置（复制/下载控制）：原站把**内容外泄控制做成一等权限项**。
→ **强烈建议目标产品保留「浏览/维护/分发」三分**，不可简化为「读/写」。

### 3.4 ⭐ 继承规则【已验证】
| 选项 | 原文说明 |
|---|---|
| **继承父分类权限** | **「勾选后使用父分类权限覆盖当前分类权限，不允许修改」** |
| **所有子分类继承当前分类权限** | **「勾选后所有子分类权限被当前分类权限覆盖，不允许修改」** |
| **在父分类中添加当前分类权限** | 配合「一键执行」按钮 |

**【已验证】** 继承是**双向可控**的：可向上继承，也可向下强制覆盖；
且**一旦启用继承，本级权限被锁定不可修改**——这是防止权限配置漂移的好设计。

## 4. ⭐⭐ 课程可见范围的完整模型【已验证】——整合 E008 §3.3

```
企课堂 College（部门级运营空间，有自己的课堂管理员/课堂成员）
  └─ 分类 Catalog（多级树）
       ├─ 是否公开：设为公开 → 全平台浏览（级联子分类）
       ├─ 权限矩阵：主体(超管&创建者 / 课堂管理员 / 课堂成员 / 指定用户)
       │              × 动作(分发 / 维护 / 浏览 / 允许下载课件 / App缓存课件)
       ├─ 继承：继承父分类权限(锁定) / 覆盖所有子分类(锁定)
       └─ 课程 Course
            ├─ 浏览权限：① 跟随分类浏览权限（默认，继承上面整套）
            │              ② 单独设置允许浏览（课程级覆盖）
            ├─ 是否隐藏：隐藏后「仅在课程或项目中使用」（不出现在自主浏览场景）
            ├─ 游客访问：支持游客访问
            └─ 分享权限：允许ta人分享
```

**【已验证】可见范围是四层叠加**：
1. **企课堂归属**（运营空间）
2. **分类权限**（主体 × 动作，可继承）
3. **课程级覆盖**（跟随分类 or 单独设置）
4. **隐藏/游客/分享**三个独立开关

**规划含义（必须写入需求基线）**：
- 「课程对某人是否可见」**不是一个布尔字段能表达的**，是上述四层的合成结果。
- V1（单闭环 MVP）建议**简化为两层**：分类权限 + 课程级覆盖，**放弃企课堂层与 App 缓存项**，并在差异清单中说明。列入 **DIFF-25**。
- 验收场景必须覆盖：「分类设为公开 → 课程跟随分类 → 预期全员可见」「课程设为隐藏 → 预期不出现在在线课堂，但项目中仍可学」。
